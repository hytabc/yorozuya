# 产品需求文档（PRD）

## 《糖霜世界》——一款基于VRChat社交主题的因果叙事解谜网页游戏

| 项目 | 内容 |
|---|---|
| 文档版本 | V1.0 |
| 产品名称（暂定） | 糖霜世界（Sugar Frost） |
| 产品类型 | 网页端文字解谜 / 互动叙事 |
| 目标平台 | 桌面浏览器（Chrome / Edge / Safari），移动端浏览器适配（P1） |
| 核心参考 | 《WILL：美好世界》的因果重组玩法 + VRChat社交文化 |
| 文档状态 | 初稿 |


## 一、项目概述

### 1.1 产品定位

《糖霜世界》是一款以VRChat虚拟社交社区为背景的文字解谜游戏。玩家扮演一位“观测者”，通过重组VRChat用户之间发生过的聊天记录、事件片段的时间顺序，修复因误解、疏离或意外而破裂的人际关系。

与《WILL：美好世界》中“神收到凡人信件”的设定类似，本作中玩家接收到的是来自VRChat用户的“聊天记录碎片”或“回忆片段”——这些片段被系统打乱，玩家需要将它们拖拽重组，改变事件的因果逻辑，从而让故事走向更好的结局。

### 1.2 核心立意

VRChat社交关系的独特之处在于：用户通过化身（Avatar）进行选择性自我呈现，在虚拟空间中获得了一种“比现实更近”的亲密感——友谊可以在短时间内迅速加深，而关系的断裂同样来得猝不及防。VRChat社区中还存在一种被称为“砂糖”的独特关系形态——比朋友更亲密，但尚未成为情侣，这种关系的建立与消解往往伴随着微妙的情感拉扯。

本作希望以游戏化的方式，让玩家体验这种虚拟社交关系中的“修复”与“理解”。

### 1.3 目标用户

- 核心用户：18–30岁，有VRChat或社交VR平台使用经验，对虚拟社交文化有共鸣
- 扩展用户：喜欢文字解谜/互动叙事游戏的玩家（《WILL：美好世界》《逆转裁判》《极限脱出》受众）
- 潜在用户：对元宇宙、虚拟社交话题感兴趣的泛互联网用户

### 1.4 设计原则

1. **叙事服务于解谜**：所有文字表现、角色关系、氛围营造均为因果解谜服务。
2. **操作极简**：核心交互仅有“拖拽”和“点击”，降低上手门槛。
3. **情感驱动**：每一关的谜题背后，都是一个能让玩家产生情感共鸣的VRChat故事。


## 二、核心玩法机制

### 2.1 主循环

```
接收碎片 → 阅读碎片 → 拖拽重组 → 因果推演 → 结局判定 → 解锁新碎片
```

### 2.2 核心交互：因果重组

玩家面对一组打乱顺序的“事件片段”（以下称“碎片”）。每个碎片是一段简短的文字描述，包含VRChat社交场景中的具体事件，例如：

- “A邀请B跳进了一个新世界（World）”
- “B在镜子前换了新的Avatar”
- “A发现B的好友列表里多了一个陌生ID”
- “B说：‘抱歉，我现在有点忙’”

玩家通过拖拽调整碎片顺序，改变事件的因果链。不同的排列组合将导向不同的结局——有的修复了关系，有的则让裂痕进一步扩大。

### 2.3 碎片类型与规则

| 碎片类型 | 说明 | 可拖拽 | 备注 |
|---|---|---|---|
| 白色碎片 | 普通事件，可自由调整顺序 | ✅ | 核心可操作元素 |
| 灰色碎片 | 固定事件，不可移动 | ❌ | 作为因果锚点 |
| 金色碎片 | 关键事件，移动后触发特殊效果 | ✅ | 如交换两人对话 |
| 红色碎片 | 负面事件，需被“覆盖”或移除 | 有条件 | 部分关卡中可被金色碎片替换 |

规则约束：碎片不可被移动到序列的最前端或最末端——这与《WILL：美好世界》的规则一致，确保每个故事有确定的起点和终点。

### 2.4 蝴蝶效应系统

当一关中存在多个角色的故事线时，玩家可以跨角色交换碎片。例如：

> 角色A的碎片“A独自在空城徘徊”与角色B的碎片“B在人群中寻找A”交换位置后，两人的故事线会在新的时间点交汇，触发隐藏剧情。

这一机制要求玩家不仅理解单个角色的故事，还要理解角色之间的关系网络。

### 2.5 结局判定

每个关卡有3–5种结局，分为三类：

- **修复结局（Good）** ：关系得到改善或维系
- **遗憾结局（Bittersweet）** ：关系走向改变但并非完美，如“砂糖”关系的自然消解
- **破碎结局（Bad）** ：关系进一步恶化

结局判定基于碎片序列的逻辑一致性评分，而非简单的“正确/错误”二分。鼓励玩家探索多种排列组合。


## 三、关卡与内容设计

### 3.1 章节结构

游戏分为四个章节，每章围绕一种VRChat社交关系主题展开：

| 章节 | 主题 | 核心情感 | 参考文化元素 |
|---|---|---|---|
| 第一章 | 初识 | 新鲜感与期待 | 第一次加入陌生World的紧张与兴奋 |
| 第二章 | 砂糖 | 暧昧与依赖 | “比朋友更亲，但还不到情侣”的微妙关系 |
| 第三章 | 裂痕 | 疏离与失落 | 好友有了“砂糖”后，自己逐渐被冷落 |
| 第四章 | 重逢 | 释怀与回归 | “今晚我依然登入，因为我还想再说一次‘欢迎回来’” |

### 3.2 典型关卡示例

**关卡 2-3：“砂糖的诞生”**

碎片池：

1. A和B连续三晚在空城聊天到天亮（灰色，固定起点）
2. B换了一个新Avatar（白色）
3. A问B：“怎么突然换了？”（白色）
4. B说：“这是特别的人送的。”（白色）
5. A在B的好友列表中发现陌生ID（白色）
6. A说“恭喜”（白色）
7. A独自坐在Just B Club的澡堂，翻看好友名单（灰色，固定终点）

目标结局：让A理解B的选择，同时保留两人之间的珍贵回忆。

关键解法：将碎片2和4分离，先放置碎片3（A的询问），再放置碎片2（B换Avatar），最后放置碎片4（B的解释）——这样A在看到Avatar变化之前就已经表达了关心，对话从“质问”变为“分享”。

### 3.3 碎片文本风格

- 每段碎片控制在 20–60 字
- 以动作描述为主，对话为辅
- 避免过于文学化的表达，保持VRChat用户日常交流的自然感
- 示例：“他在World列表里翻了好久，最后停在那个两人一起去过的星空房间。”


## 四、系统功能需求

### 4.1 功能优先级

| 优先级 | 功能模块 | 说明 |
|---|---|---|
| P0 | 因果重组核心玩法 | 碎片拖拽、排序、结局判定 |
| P0 | 关卡管理系统 | 关卡加载、碎片数据管理、结局记录 |
| P0 | 存档系统 | 基于浏览器LocalStorage的进度保存 |
| P1 | 多结局收集与图鉴 | 已解锁结局的展示与回看 |
| P1 | 碎片提示系统 | 卡关时提供有限提示 |
| P1 | 移动端触控适配 | 响应式布局与触摸拖拽 |
| P2 | 碎片收藏册 | 收集所有碎片文本，作为附加内容 |
| P2 | 音效与氛围音乐 | 环境音效与情感配乐 |
| P2 | 成就系统 | 完成特定排列组合解锁成就 |

### 4.2 拖拽交互详细需求

- 拖拽方式：HTML5 Drag and Drop API，桌面端支持鼠标拖拽，移动端支持触摸拖拽
- 碎片卡片高度自适应文本长度
- 拖拽时被拖拽碎片半透明跟随光标/手指
- 目标位置显示插入指示线
- 释放后自动重排布局
- 不可拖拽的碎片（灰色）在拖拽开始时显示禁用样式（降低透明度 + 禁止光标）
- 拖拽结束后，若序列发生变化，自动触发结局预判动画

### 4.3 结局预判与反馈

- 每次拖拽操作完成后，系统对当前序列进行快速逻辑评估
- 若序列为已解锁的结局组合，显示对应结局预览（文字摘要 + 情感色调）
- 若序列为未探索组合，显示“因果稳定中……”的过渡状态，2秒后展示结局
- 结局展示后，提供“保留此结局”或“重新排列”选项


## 五、技术架构

### 5.1 推荐技术栈

| 层级 | 技术选型 | 理由 |
|---|---|---|
| 前端框架 | Svelte 5 或 Astro + Svelte | 轻量、编译时优化、适合内容驱动的交互应用 |
| 样式 | Tailwind CSS | 快速构建响应式UI，支持暗色主题 |
| 拖拽交互 | 原生HTML5 Drag & Drop + Pointer Events | 无需重型库，移动端兼容良好 |
| 状态管理 | Svelte Stores | 轻量级响应式状态管理 |
| 数据存储 | LocalStorage（进度） + IndexedDB（已见文本节点） | 无需后端，纯前端方案 |
| 构建工具 | Vite | 快速开发与构建 |
| 部署 | Vercel / Netlify 静态托管 | 零服务器成本 |

对于轻量级网页叙事游戏，纯前端架构是可行的——静态脚本存储碎片数据和结局逻辑，运行时通过前端状态机驱动叙事流程。

### 5.2 数据模型

碎片数据结构（JSON）：

```json
{
  "id": "frag_2_3_05",
  "levelId": "2-3",
  "type": "white",
  "text": "A在B的好友列表中发现陌生ID",
  "order": 5,
  "character": "A",
  "tags": ["discovery", "jealousy"]
}
```

关卡数据结构：

```json
{
  "id": "2-3",
  "title": "砂糖的诞生",
  "chapter": 2,
  "fragments": ["frag_2_3_01", "..."],
  "endings": [
    {
      "id": "good_01",
      "type": "good",
      "condition": "sequence_hash",
      "text": "A理解了B的选择...",
      "thumbnail": "ending_good_01.webp"
    }
  ]
}
```

结局判定逻辑：由于碎片排列组合数量随碎片数增长呈阶乘级上升，采用“逻辑分类 + 结局映射表”方案，将排列组合按因果逻辑归纳为有限类别，每类对应一个结局。

### 5.3 性能要求

- 首屏加载时间 < 3秒（4G网络）
- 关卡切换延迟 < 500ms
- 拖拽操作响应延迟 < 50ms
- 支持同时渲染最多 12 个碎片卡片


## 六、视觉与氛围设计

### 6.1 视觉风格

- 整体基调：低饱和度的冷色调为主，辅以暖色点缀，呼应VRChat夜晚世界的氛围
- 碎片卡片：类似纸质卡片的质感，带有轻微的噪点纹理
- 拖拽反馈：碎片被拿起时投射柔和阴影，释放时卡片有轻微的“落定”动画
- 结局展示：全屏淡入淡出，配以对应结局色调的渐变背景

### 6.2 角色呈现

不绘制具体角色立绘，而是通过文字描述和碎片色调来暗示角色性格。每个角色有专属的碎片背景色和边框风格：

- 角色A：淡蓝色边框，碎片背景 #EEF3F8
- 角色B：浅橙色边框，碎片背景 #FBF3EE
- 角色C：淡紫色边框，碎片背景 #F3EEFB

### 6.3 音效设计（P2）

- 碎片拖拽：轻微的纸张摩擦声
- 碎片落位：清脆的“咔嗒”声
- 结局解锁：根据结局类型播放不同的氛围音
- 背景音乐：低音量环境电子乐，参考VRChat世界中的氛围音乐


## 七、商业化与运营设想（P2，非核心）

- 本作定位为**免费网页游戏**，主要目的是文化表达与情感共鸣
- 可选扩展：章节DLC（新增主题章节）、碎片收藏册扩展包
- 考虑在游戏内嵌入VRChat社区相关内容推荐（需合规审查）


## 八、开发路线图

| 阶段 | 内容 | 预计周期 |
|---|---|---|
| 原型验证 | 实现单关卡因果重组核心玩法 + 拖拽交互 | 2周 |
| MVP | 完成第一章（3个关卡）+ 存档系统 + 基础UI | 4周 |
| Alpha | 完成第一、二章（6个关卡）+ 结局系统 + 响应式适配 | 4周 |

| 发布 | 优化 + 测试 + 部署 | 2周 |

总计：约16周（4个月），适用于1–2人小团队。


## 九、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 排列组合数量爆炸导致结局设计困难 | 高 | 采用逻辑分类法，将组合归纳为有限类别；控制单关卡碎片数不超过8个 |
| 纯前端拖拽在移动端体验不佳 | 中 | 优先保证桌面端体验，移动端作为P1适配，使用Pointer Events统一处理 |
| VRChat文化圈层较窄，受众有限 | 中 | 通过情感共鸣（友情、失落、释怀）拓展非VRChat用户 |
| 因果逻辑不够直观，玩家卡关 | 中 | 提供渐进式提示系统，首次卡关时给出方向性引导而非直接答案 |


## 十、验收标准

1. 玩家可在桌面浏览器中完成至少12个关卡的因果重组解谜
2. 每个关卡至少包含3种可解锁结局
3. 拖拽交互流畅，无卡顿或误触
4. 游戏进度在刷新页面后可恢复
5. 核心玩法在不阅读任何教学文本的情况下，通过第一个教学关卡即可理解
