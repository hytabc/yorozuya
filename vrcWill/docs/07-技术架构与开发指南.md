# 07 · 技术架构与开发指南

> 本文定义工程结构、状态管理、存档迁移、i18n、性能预算与部署方案。

---

## 一、技术栈

| 层级 | 选型 | 理由 |
|---|---|---|
| 前端框架 | Svelte 5 | 编译时优化，无虚拟 DOM，适合内容驱动的交互应用 |
| 构建 | Vite 5 | 快速冷启动、原生 ESM、内置代码分割 |
| 样式 | 原生 CSS + 自定义属性 | 避免引入 Tailwind 的类名噪音；Token 体系见 docs/04 |
| 状态 | Svelte 5 Runes（`$state` / `$derived`） | 细粒度响应式，无需额外状态库 |
| 拖拽 | Pointer Events（自实现） | 不依赖库；桌面/移动端统一；可控性最高 |
| 存储 | LocalStorage（进度）+ IndexedDB（文本） | 纯前端，零后端成本 |
| 测试 | `node:test`（引擎）+ Playwright（E2E） | 引擎零依赖可测；E2E 覆盖拖拽 |
| 部署 | Vercel / Netlify 静态托管 | 零服务器成本 |

> **判定引擎不依赖任何框架**，是纯 TypeScript 模块。这样它可以被 Node 直接运行（校验器、测试），也可以被 Svelte 直接引入。

### 2.1 分层依赖规则（必须遵守）

```
routes/  →  components/  →  stores/  →  engine/  →  data/
   ↓            ↓             ↓           ↓
 (可有 UI)   (只读状态)    (可写状态)  (纯函数)   (纯数据)
```

**禁止反向依赖。**

- `engine/` 不得 import 任何 `stores/`、`components/`、Svelte 相关模块；
- `data/` 不得 import 任何代码；
- `engine/` 内部只允许 `types.ts` 被所有模块依赖。

这条规则是"引擎可在 Node 中直接运行"的前提，破坏了它，`tools/verify-levels.ts` 和 `tests/engine.test.ts` 立刻失效。

## 三、状态管理

### 3.1 game store（关卡状态机）

```ts
// src/lib/stores/game.svelte.ts
import type { Level, JudgeResult } from '$lib/engine/index.ts';

export type LevelPhase =
  | 'loading' | 'reading' | 'arranging' | 'previewing'
  | 'settling' | 'revealing' | 'result' | 'unlocked';

class GameStore {
  level = $state<Level | null>(null);
  chain = $state<string[]>([]);
  phase = $state<LevelPhase>('loading');
  undoStack = $state<string[][]>([]);

  // 派生：不需要手动同步
  draggable = $derived(this.level ? computeDraggable(this.chain, this.level) : new Set<string>());
  coherence = $derived(this.level ? computeCoherence(this.chain, this.level) : 0);
  valence   = $derived(this.level ? computeChainValence(this.chain, this.level) : 0);

  canUndo = $derived(this.undoStack.length > 0);
  canSubmit = $derived(
    this.phase === 'arranging' || this.phase === 'previewing'
  );

  move(fragmentId: string, toIndex: number) { /* ... */ }
  undo() { /* ... */ }
  submit(): JudgeResult { /* ... */ }
}
```

**关键约束：**

1. `coherence` / `valence` 必须用 `$derived`，不手动同步——避免状态不一致。
2. 每次 `move()` 前把当前链压入 `undoStack`，上限 20。
3. `move()` 后若链变化，phase → `previewing`，并触发一次预判。

### 3.2 progress store（存档）

```ts
class ProgressStore {
  slot = $state<SaveSlot | null>(null);

  endingsSeen = $derived(new Set(this.slot?.endingsSeen ?? []));
  isLevelCleared = $derived((id: string) => this.slot?.progress.cleared.includes(id) ?? false);

  recordEnding(levelId: string, ending: Ending) { /* 写档 + 羁绊 + 解锁判定 */ }
  unlockNextLevel(levelId: string) { /* ... */ }
  addBond(effect: Partial<Record<CharacterId, number>>) { /* 夹取到 -100..100 */ }
}
```

### 3.3 自动保存

- 触发时机：结局结算后、离开关卡时、每 30 秒（仅在 `dirty` 时）。
- 写入失败（如配额超限）：降级到只保存进度字段，丢弃 IndexedDB 文本缓存。

## 四、存档迁移

### 4.1 版本策略

`SCHEMA_VERSION` 定义于 `types.ts`，当前为 `2`。

```ts
// src/lib/utils/migrate.ts
type Migration = (data: any) => any;

const MIGRATIONS: Record<number, Migration> = {
  // v1 → v2：新增 butterfliesSeen 与 bond
  1: (d) => ({
    ...d,
    version: 2,
    slots: d.slots.map((s: any) => ({
      ...s,
      butterfliesSeen: s.butterfliesSeen ?? [],
      bond: s.bond ?? { Mio: 0, Shiori: 0, Rin: 0, Yu: 0 },
      hintsUsed: s.hintsUsed ?? {},
    })),
  }),
};

export function migrate(raw: any): SaveFile {
  let data = raw;
  while (data.version < SCHEMA_VERSION) {
    const m = MIGRATIONS[data.version];
    if (!m) throw new Error(`缺少 v${data.version} 的迁移函数`);
    data = m(data);
  }
  return data as SaveFile;
}
```

### 4.2 容错

```
读取存档
  ├─ JSON.parse 失败
  │    → 备份原文到 `sugarfrost.save.bak`
  │    → 创建新档
  │    → 提示玩家「存档已损坏，已备份并重置」
  ├─ 版本号 > 当前
  │    → 不读取（避免损坏），提示「存档来自更新的版本」
  └─ 迁移抛异常
       → 同「解析失败」处理
```

## 五、i18n

### 5.1 现状

当前所有文案**以中文硬编码在关卡 JSON 中**（`fragment.text`、`ending.text` 等），这是有意的简化：

- 文案量约 1.2 万字，全部集中在 12 个 JSON 文件中；
- 文案与数据结构强绑定（碎片文案即碎片内容），拆成 key-value 反而增加维护成本。

### 5.2 未来多语言的迁移路径

**第 1 步**：抽出 `src/lib/i18n/zh-CN.ts`，把 JSON 中的 `text` 替换为 `textKey`：

```json
{ "id": "frag_2_3_02", "textKey": "frag.2_3.02" }
```

```ts
export const zhCN = {
  'frag.2_3.02': 'B 换了一个新 Avatar。',
  'ending.2_3.good.title': '先问再说',
  // ...
};
```

**第 2 步**：新增 `en-US.ts`，类型由 `typeof zhCN` 约束，保证不漏 key。

**第 3 步**：`Fragment.text` 改为 getter，通过 `t(fragment.textKey)` 解析。

### 5.3 UI 文案

UI 层文案（按钮、提示、错误）**现在就应该走 key**，因为这些文案数量少、变更频繁：

```ts
// src/lib/utils/i18n.ts
export const UI = {
  'action.submit': '让因果稳定',
  'action.retry': '重新排列',
  'action.keep': '保留此结局',
  'meter.coherence': '因果连贯度',
  'meter.valence': '情感走向',
  'hint.title': '线索',
  'error.data_load': '关卡数据加载失败。请检查网络后重试。',
  // ...
} as const;

export type UIKey = keyof typeof UI;
export function t(key: UIKey): string { return UI[key]; }
```

## 六、性能预算

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 首屏加载（4G） | < 3s | Lighthouse |
| 首包体积 | < 300KB gzip | `vite build` 报告 |
| 关卡切换 | < 500ms | Performance API |
| 拖拽响应 | < 50ms | 手动 + Performance API |
| 判定引擎单次 | < 5ms | `tests` 中的基准 |
| 同时渲染碎片 | ≤ 12 | 本作上限 9 |
| 内存占用 | < 80MB | Chrome DevTools |

### 6.1 优化手段

| 手段 | 说明 |
|---|---|
| 关卡数据懒加载 | `import()` 按需加载 JSON，配合 `manualChunks` 按章节拆分 |
| 引擎 tree-shaking | 纯函数、无副作用，未使用的分支自动摇掉 |
| 拖拽用 CSS transform | 不触发 layout，只触发 composite |
| 雪花粒子用 canvas | 避免 60 个 DOM 节点的重排 |
| 图片用 WebP | 结局缩略图总计 < 800KB |
| 字体子集化 | 只打包实际用到的中文字形 |
| 指标条用 `width` + `will-change` | 单独提升为合成层 |

## 七、开发工作流

### 7.1 环境要求

- Node ≥ 22.6（需要原生 TypeScript type stripping）
- 包管理器：npm / pnpm

### 7.2 常用命令

```bash
node tools/verify-levels.ts          # 校验全部关卡（改数据后必跑）
node tools/verify-levels.ts 2-3      # 只校验单个关卡
node --test tests/engine.test.ts     # 引擎单测
npm run dev                          # 开发服务器
npm run build                        # 生产构建
npm run typecheck                    # 类型检查
```

### 7.3 修改关卡数据的标准流程

```
① 编辑 src/lib/data/levels/<id>.json
② node tools/verify-levels.ts <id>
   ├─ 全部 ✓ → 继续
   └─ 有 ✗ → 按提示调整权重/阈值
③ node --test tests/engine.test.ts
④ 在浏览器中实际玩一遍，确认文案与手感
```

### 7.4 提交前检查清单

- [ ] `node tools/verify-levels.ts` 全绿
- [ ] `node --test tests/engine.test.ts` 全绿
- [ ] `npm run typecheck` 无错误
- [ ] `npm run build` 通过且首包 < 300KB
- [ ] 新文案不含硬编码碎片 ID（提示文本除外，用于 highlight 字段）

## 八、部署

### 8.1 静态托管

Vercel / Netlify，构建命令 `npm run build`，输出目录 `dist`。

### 8.2 缓存策略

| 资源 | Cache-Control |
|---|---|
| `index.html` | `no-cache` |
| `assets/*.[hash].js` | `public, max-age=31536000, immutable` |
| `assets/*.[hash].css` | 同上 |
| `audio/*` | `public, max-age=604800` |
| `endings/*.webp` | `public, max-age=31536000, immutable` |

### 8.3 无后端承诺

本作**不需要任何服务器端逻辑**：

- 存档在玩家浏览器本地；
- 无账号系统、无排行榜、无云同步；
- 无用户数据上传。

这也意味着：**玩家的存档只存在于这一台设备的这一个浏览器中**。UI 需要明确提示这一点，避免玩家误以为有云存档。

## 九、已知限制与后续扩展

| 限制 | 影响 | 后续方案 |
|---|---|---|
| 无云存档 | 换设备丢失进度 | 后续可加"导出/导入存档 JSON"功能 |
| 移动端拖拽手感 | 长按 200ms 仍不如原生顺滑 | 可考虑 WebView 原生桥接，或简化为点击交换 |
| 文案硬编码 | 难以多语言 | 按 §5.2 的三步迁移 |
| 单关碎片上限 7 | 复杂叙事受限 | 若需 > 7，需为校验器加入抽样而非穷举 |
| 无服务端 | 无法做数据埋点分析 | 可接入 Vercel Analytics 或自建轻量上报 |

## 十、代码规范

| 项目 | 约定 |
|---|---|
| 语言 | TypeScript strict 模式 |
| 模块导入 | **必须带 `.ts` 后缀**（保证 Node 直接运行） |
| 禁止 | `enum` / `namespace` / 装饰器 / 参数属性（Node type stripping 不支持） |
| 注释 | 只在"为什么"不显然时写；不写"是什么" |
| 命名 | 类型 PascalCase；函数/变量 camelCase；常量 UPPER_SNAKE |
| 中文标识 | 仅用于 `character` 枚举值与数据内容，代码标识符一律英文 |
| 副作用 | `engine/` 内禁止任何副作用 |
