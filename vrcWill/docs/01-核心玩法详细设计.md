# 01 · 核心玩法详细设计

> 本文定义《糖霜世界》的玩法规则、状态机、交互流程、碎片类型行为与边界处理。
> 引擎实现见 `src/lib/engine/`；关卡数据见 `src/lib/data/levels/`。

---

## 一、核心循环

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│   ① 进入关卡  →  ② 阅读碎片  →  ③ 拖拽重组  →  ④ 因果预判      │
│        ↑                                          ↓          │
│        │                                    ⑤ 提交判定        │
│        │                                          ↓          │
│        └──── ⑧ 解锁新内容  ←  ⑦ 结算  ←  ⑥ 结局展示          │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

| 阶段 | 玩家行为 | 系统响应 | 可跳过 |
|---|---|---|---|
| ① 进入关卡 | 从章节页点击关卡 | 全屏淡入（400ms），显示标题、涉及角色、开场文本 | 否 |
| ② 阅读碎片 | 悬停 / 点击碎片卡片 | 卡片展开完整文本，显示角色色边框 | 否 |
| ③ 拖拽重组 | 拖动碎片到目标槽位 | 半透明卡片跟随；目标位置显示插入指示线 | 否 |
| ④ 因果预判 | — | 拖拽结束后自动评估，更新两根指标条 | 否 |
| ⑤ 提交判定 | 点击「让因果稳定」 | 播放 2 秒「因果稳定中……」过渡 | 否 |
| ⑥ 结局展示 | — | 全屏淡入，配对应色调渐变与结局文本 | 可点击跳过动画 |
| ⑦ 结算 | 选择「保留此结局」/「重新排列」 | 记录结局、更新羁绊值、判定解锁 | 否 |
| ⑧ 解锁新内容 | — | 解锁下一关 / 蓝色碎片 / 幕后注释 / 成就 | 否 |

## 二、状态机

### 2.1 关卡级状态机

```
                    ┌──────────┐
                    │  loading │
                    └────┬─────┘
                         │ 数据就绪
                    ┌────▼─────┐
              ┌─────┤  reading │◄────────────┐
              │     └────┬─────┘             │
              │          │ 首次拖拽           │ 「重新排列」
              │     ┌────▼─────┐             │
              │     │ arranging│             │
              │     └────┬─────┘             │
              │          │ 落位                │
              │     ┌────▼──────┐            │
              │     │ previewing│            │
              │     └────┬──────┘            │
              │          │ 点击"让因果稳定"     │
              │     ┌────▼─────┐             │
              │     │ settling │  (2s)       │
              │     └────┬─────┘             │
              │          │ 判定完成            │
              │     ┌────▼─────┐             │
              │     │ revealing│             │
              │     └────┬─────┘             │
              │          │ 动画结束            │
              │     ┌────▼─────┐             │
              └─────┤  result  ├─────────────┘
                    └────┬─────┘
                         │ 选择「保留此结局」
                    ┌────▼─────┐
                    │ unlocked │  → 返回章节页 / 下一关
                    └──────────┘
```

### 2.2 状态迁移表

| 当前状态 | 事件 | 下一状态 | 副作用 |
|---|---|---|---|
| `loading` | 数据加载完成 | `reading` | 播放进入动画 |
| `reading` | 玩家首次按下一枚碎片 | `arranging` | 记录初始链快照（供撤销） |
| `arranging` | 碎片落位 | `previewing` | 重算连贯度/情感值 |
| `arranging` | 撤销（⌘/Ctrl+Z） | `arranging` | 回退一步 |
| `previewing` | 继续拖拽 | `arranging` | — |
| `previewing` | 点击「让因果稳定」 | `settling` | 禁用交互，启动 2s 计时 |
| `settling` | 计时结束 | `revealing` | 播放结局动画 |
| `revealing` | 动画播放完 | `result` | 显示结算面板 |
| `result` | 点击「重新排列」 | `arranging` | 保留当前链 |
| `result` | 点击「保留此结局」 | `unlocked` | 写入存档、更新羁绊、判定解锁 |
| 任意 | 按 ESC | （返回章节页） | 若链已改动则弹确认 |

### 2.3 状态与可拖拽性的关系

| 状态 | 碎片可拖拽 | 提交按钮 | 提示按钮 |
|---|---|---|---|
| `reading` | ✅ | ✅ | ✅ |
| `arranging` | ✅ | ✅ | ✅ |
| `previewing` | ✅ | ✅ | ✅ |
| `settling` | ❌ | ❌ | ❌ |
| `revealing` | ❌ | ❌ | ❌ |
| `result` | ❌ | ❌ | ❌ |
| `unlocked` | ❌ | ❌ | ❌ |

## 三、碎片系统

### 3.1 五类碎片

| 类型 | 视觉 | 可拖拽 | 入链 | 行为 |
|---|---|---|---|---|
| **white 白色** | 纸白卡片 + 角色色边框 | ✅ | ✅ | 普通事件，自由排序 |
| **gray 灰色** | 灰度卡片 + 锁形角标 | ❌ | ✅（仅首尾） | 因果锚点，固定不动 |
| **gold 金色** | 金色描边 + 微光呼吸动画 | ✅ | ✅ | 落位时与相邻碎片触发"语义交换"演出 |
| **red 红色** | 暗红描边 + 裂纹纹理 | 条件性 | ✅ | 默认锁定；被解锁后可拖拽 |
| **blue 蓝色** | 冷蓝描边 + 水波纹 | ❌ | ❌ | 内心独白，不入链，仅作为情感线索展示 |

### 3.2 锚点规则（铁律）

> **碎片不可被移动到序列的最前端或最末端。**

- 首位与末位由 `level.anchors.first` / `level.anchors.last` 两个灰色碎片占据。
- 可拖拽区间为 `[1, chainLength-2]`（0-based）。
- 若玩家把碎片拖向首尾槽位，插入指示线不显示，卡片回弹。
- `validateChain()` 会在开发期断言这一点。

### 3.3 灰色碎片的锁定表现

- 悬停：光标变为 `not-allowed`，卡片轻微降低亮度（`filter: brightness(0.96)`）。
- 尝试拖拽：卡片水平抖动 8px（120ms），并显示一行淡字提示「这是固定的起点」。

### 3.4 金色碎片机制

金色碎片**不改变链的结构**，而是**改变相邻碎片的语义**。

**实现约定（引擎层）**：金色碎片就是一枚普通的可拖拽碎片，与其他碎片一样参与约束判定。"交换"是 UI 层的演出效果：

1. 金色碎片落位时，检测其左右邻居；
2. 若邻居是白色碎片，播放一次 600ms 的"文字溶解—重组"动画；
3. 动画结束后，被影响的白色碎片临时显示一行金色小字补充语义（补充文案存在 `Fragment.note` 之外的 UI 文案表中）。

**设计目的**：让玩家意识到"位置本身携带信息"。

**各关金色碎片一览：**

| 关卡 | 碎片 | 语义效果 |
|---|---|---|
| 2-2 | `frag_2_2_04` | 与「新形象很好看」相邻时，揭示那套配色叫「澪蓝」 |
| 2-3 | `frag_2_3_04` | 与「怎么突然换了」相邻时，补全"特别的人"的主语 |
| 3-3 | `frag_3_3_04` | 与该关任意碎片相邻时，调转叙述视角 |
| 4-2 | `frag_4_2_07` | 决定凛是"继续等待"还是"终于转身" |
| 4-3 | `frag_4_3_08` | 决定这是"最后一次登入"还是"第一次回来" |

### 3.5 红色碎片机制

红色碎片代表**真实存在的负面念头**，它不能被消灭，只能被处理。

**默认状态**：锁定，不可拖拽（`draggable: false` 由关卡数据决定）。

**解锁条件**（由 `Level.redUnlock` 定义）：

```json
{
  "redFragmentId": "frag_3_1_04",
  "requires": [
    { "kind": "adjacent", "a": "frag_3_1_05", "b": "frag_3_1_04", "weight": 0 }
  ]
}
```

即：当另一枚碎片被放到红色碎片旁边时，红色碎片被"淡化"为普通白卡，解锁拖拽。

**当前版本**：3-1 的红色碎片 `frag_3_1_04` 在数据中直接 `draggable: true`（因为它位于本关因果的核心位置，若不移动则无法达成任何结局）。`Level.redUnlock` 机制保留给后续扩展关卡。

**视觉表现**：

| 状态 | 表现 |
|---|---|
| 锁定 | 暗红边框 + 裂纹 + 灰度 60% |
| 解锁瞬间 | 裂纹淡出（400ms），饱和度回升至 100% |
| 解锁后 | 与其他白色碎片一致，仅保留暗红边框作为提示 |

### 3.6 蓝色碎片机制

蓝色碎片是**内心独白**，具备三个特性：

1. **不入链**：不出现在 `initialOrder` 中，不参与任何约束判定；
2. **不可拖拽**：`draggable: false`；
3. **条件解锁**：通过 `unlockedBy` 字段定义解锁条件。

**解锁条件语法：**

| 语法 | 含义 | 示例 |
|---|---|---|
| `ending:<levelId>:<type>` | 通关某关的某类型结局 | `ending:1-3:good` |
| `endingType:<type>` | 任意关卡达成某类型结局 | `endingType:true` |
| `butterfly:<levelId>:<id>` | 触发某关的某蝴蝶效应 | `butterfly:3-3:A` |

**展示方式**：解锁后在关卡页右下方以淡蓝卡片形式常驻显示，鼠标悬停展开全文。不占用因果链空间。

## 四、拖拽交互详细流程

### 4.1 桌面端（鼠标）

```
① pointerdown on 卡片
   ├─ 若卡片不可拖拽 → 播放抖动 + 提示，结束
   └─ 否则：记录起点，进入 pending 状态
② pointermove 超过 4px 阈值
   ├─ 卡片 opacity → 0.6，scale → 1.02，阴影加深
   ├─ 创建"跟手"的浮层副本
   └─ 原位置留下占位虚线框
③ 拖拽中
   ├─ 计算最近的插入点（基于卡片中线与槽位中线的距离）
   ├─ 在插入点显示 2px 高的指示线（角色主色）
   ├─ 若插入点在首/末槽位 → 不显示指示线（不可放置）
   └─ 自动滚动：接近视口边缘 80px 时按 8px/帧 滚动
④ pointerup
   ├─ 有效落点 → 卡片插入，播放 180ms"落定"缓动（cubic-bezier(.2,.8,.3,1)）
   ├─ 无效落点（首尾/越界） → 卡片回弹（220ms spring）
   └─ 落点未变化 → 不做任何事
⑤ 落位后
   ├─ 若链发生变化 → 触发预判（④ 因果预判）
   └─ 压入撤销栈（最多 20 步）
```

### 4.2 移动端（触摸）

- 使用 **Pointer Events** 统一处理，不依赖 HTML5 DnD。
- **长按 200ms** 激活拖拽（避免与页面滚动冲突）。
- 激活时提供 **10ms 短震动**（`navigator.vibrate(10)`，不支持则静默）。
- 拖拽中禁止页面滚动（`touch-action: none` on 卡片）。
- 落点判定阈值放宽到 48px（手指遮挡补偿）。

### 4.3 键盘无障碍

| 操作 | 按键 |
|---|---|
| 聚焦碎片 | `Tab` / `Shift+Tab` |
| 上移一位 | `Ctrl`/`⌘` + `↑` |
| 下移一位 | `Ctrl`/`⌘` + `↓` |
| 移到首位/末位（可动区间内） | `Ctrl`/`⌘` + `Home` / `End` |
| 确认（提交） | `Enter`（在提交按钮上） |
| 撤销 | `Ctrl`/`⌘` + `Z` |

聚焦时通过 `aria-live="polite"` 播报当前序号，例如：
> 「碎片 3，共 5 枚。『B 换了一个新 Avatar』。按 Ctrl 加向上箭头可上移。」

## 五、因果预判与反馈

### 5.1 两根指标条

拖拽落位后立即更新，无需点击提交：

| 指标 | 范围 | 色彩 | 计算 |
|---|---|---|---|
| **因果连贯度 Coherence** | 0–100 | 冷蓝 `#7BA7C7` | `max(matchRate(e)) × 100` |
| **情感走向 Valence** | -100 ~ +100 | 暖金 → 冷灰渐变 | 链中碎片 valence 均值归一化 |

**连贯度分档反馈：**

| 区间 | 表现 |
|---|---|
| 0–29 | 指标条灰暗，无文字 |
| 30–59 | 指标条正常，下方显示「因果还不稳定」 |
| 60–79 | 指标条微光，「似乎有某种走向」 |
| 80–100 | 指标条发光，「因果已经稳定」 |

### 5.2 预判状态机

```
落位 → evaluate()
        ├─ 命中已解锁结局 且 匹配率 ≥ 0.75 → 直接预览结局摘要（不等待）
        ├─ 命中已解锁结局 但 匹配率 < 0.75 → 显示"因果稳定中……"，2s 后展示
        └─ 未命中任何结局 → 显示"因果未能稳定"，引导继续调整
```

> **注意**：预判只**展示倾向**，不直接给出结局名。结局名只在点击「让因果稳定」后揭示。这样保留"提交"这一动作的仪式感。

### 5.3 结算界面

结局展示后提供两个选项：

| 选项 | 行为 |
|---|---|
| **保留此结局** | 写入存档；更新羁绊值；判定解锁（下一关 / 蓝色碎片 / 成就 / 幕后注释）；返回章节页 |
| **重新排列** | 保留当前链，回到 `arranging` 状态 |

> 若该结局此前已解锁，界面额外显示「这个结局你已经见过了」与本次的排列对照。

## 七、提示系统

### 7.1 三级提示

| 层级 | 触发条件 | 内容 | 惩罚 |
|---|---|---|---|
| **L1 方向性** | 累计 3 次未通关提交 | 描述因果方向，不点破具体碎片 | 成就「不用提示的人」失效 |
| **L2 高亮** | 累计 6 次 | 高亮一对待调整顺序的碎片 | 同上 |
| **L3 直接** | 累计 10 次 | 展示推荐序列片段 | 同上 |

**「未通关提交」的定义**：提交后命中的结局类型为 `chaos`，或命中的是 `bad` 结局。命中 `good` / `bittersweet` / `true` 后计数清零。

### 7.2 主动规则说明

点击右上角「?」随时可查看当前关卡的规则说明（`getRuleHint()`），内容包括：
- 基础操作说明
- 本关涉及的碎片类型解释（按实际存在的类型动态生成）
- **不含任何解法信息**

### 7.3 提示文案要求

- 不得出现碎片 ID
- 不得直接给出完整序列（除 L3）
- 优先使用"顺序/因果"的语言，而非"正确答案"的语言

## 八、边界与异常处理

| 场景 | 处理 |
|---|---|
| 链中存在重复碎片 | `validateChain()` 报错，开发期断言；线上降级为混沌结局 |
| 约束引用了链中不存在的碎片 | `matchConstraint()` 返回 `false`（不抛异常） |
| 隐藏碎片未解锁但约束引用了它 | 同上，自动不可命中 |
| 关卡数据加载失败 | 显示错误页 + 「重试」按钮；不阻塞其他关卡 |
| 存档解析失败 | 备份原数据到 `localStorage.bak`，重置为新档，提示玩家 |
| 存档版本号低于当前 | 执行迁移函数链；迁移失败则重置 |
| 玩家在中途关闭页面 | `beforeunload` 与每 30s 自动保存 |
| 拖拽中失去指针（如切窗口） | `pointercancel` → 卡片回弹，状态回 `arranging` |
| 同时按下多个指针 | 只响应第一个指针，其余忽略 |
| 视口过窄（< 360px） | 强制单列布局，碎片卡片字体降到 13px |
| 减少动效开启 | 所有过渡时长降为 0ms；结局直接切换 |
| 色盲模式开启 | 角色边框改为高对比 + 形状标识强化 |
| 图鉴中图片缺失 | 回退到结局类型的纯色渐变 |

## 九、数值与平衡

### 9.1 统一 100 分制

**所有关卡的所有结局，其正向约束权重之和恒等于 100。**

理由：判定引擎按原始得分排序取最高者。如果各结局满分不同，会出现"一个 100% 匹配的 bad 结局输给 60% 匹配的 good 结局"的错误。统一满分后，得分即匹配率，排序公平且语义清晰。

该约束由 `tools/verify-levels.ts` 强制校验。

### 9.2 阈值梯度

| 结局类型 | 阈值 | 含义 |
|---|---|---|
| `true`（隐藏） | 75 | 最难达成，需要额外条件 |
| `good`（修复） | 70 | 需要正确理解因果 |
| `bittersweet`（遗憾） | 60 | 较容易误入 |
| `bad`（破碎） | 55 | 提醒玩家"这样会变糟" |
| `chaos`（混沌） | — | 兜底，不参与阈值 |
