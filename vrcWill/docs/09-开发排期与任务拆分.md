## 四、并行化建议（1 人 / 2 人）

### 4.1 单人开发

关键路径：**T5 拖拽 → 全部 UI → 全量内容**。

建议顺序：

```
W1–2   M1 原型（2-3 单关）
W3–6   M2 MVP（第一章 + 存档）
W7–10  M3 Alpha（前两章 + 图鉴 + 响应式）
W11–14 M4 Beta（全 12 关 + 音效 + 羁绊）
W15–16 M5 发布
```

**单人的最大风险是内容打磨被压缩**。由于本套设计包已把文案与数值全部定稿（含 45 个结局的完整文本），这部分工作量已大幅前置，是单人可行的重要前提。

### 4.2 两人开发

| 时段 | 开发者 A（前端） | 开发者 B（内容/美术） |
|---|---|---|
| W1–2 | T1/T4/T5/T6/T7 全部 | Design Token、碎片卡片视觉、图标 |
| W3–6 | T9/T10/T8/T5-6 | 第一章美术细化、结局缩略图 |
| W7–10 | T11/T14 | 第二三章缩略图、雪花纹理 |
| W11–14 | T12/T13/T15 | 音频资源、动效细化 |
| W15–16 | T16/T17 | 宣传素材 |

**并行前提**：Design Token 必须最先冻结（T1-2），否则 A 的组件与 B 的视觉会持续返工。

## 五、风险登记

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| 拖拽在移动端体验不佳 | 高 | 中 | 先保桌面端；移动端降级为"点击选中→点击落位"模式 |
| 首包超过 300KB | 中 | 中 | 关卡数据按章节懒加载；字体子集化；图标内联 SVG |
| 内容打磨时间被挤压 | 中 | 高 | 文案与数值已定稿（本设计包），只剩手感调优 |
| 音效资源无法产出 | 中 | 低 | 音频为 P2，有完整降级方案（docs/05 §9） |
| 单人开发周期超预期 | 中 | 中 | M2 后砍 P2 功能（成就、音效），保 M4 内容完整 |
| 结局数值平衡出问题 | 低 | 高 | 已用穷举校验器验证 45/45 可达，改动后必跑校验 |
| 存档格式变更导致玩家丢档 | 低 | 高 | 迁移函数 + 备份机制（docs/07 §4） |

## 六、砍需求顺序（若工期不足）

按以下顺序砍，**从下往上砍**：

| 顺序 | 功能 | 影响 |
|---|---|---|
| 7 | 成就系统 | 无核心影响 |
| 6 | 音效与 BGM | 氛围减弱，玩法完整 |
| 5 | 碎片收藏册（P2） | 附加内容 |
| 4 | 移动端适配 | 桌面端仍可玩 |
| 3 | 结局图鉴 | 玩家少一个回看入口，但不影响通关 |
| 2 | 幕后注释 | 附加内容 |
| 1 | 羁绊值与全局结局 | **不可砍**——这是全作情感落点 |

**红线（永不砍）：**

1. 12 个关卡（PRD 验收标准 §13.1）
2. 每关 ≥ 3 个结局（§13.2）
3. 3-2 的"放手"设计（§13.7）——这是本作的立意所在
4. 全局结局分支（§13.8）
