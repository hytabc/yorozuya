# 一、项目概述

## 1.1 产品定位

《糖霜世界》是一款以 VRChat 虚拟社交社区为背景的**文字解谜 / 互动叙事**游戏。玩家扮演"观测者"，通过拖拽重组 VRChat 用户之间发生过的聊天记录、事件片段的时间顺序，改变事件的因果逻辑，从而修复因误解、疏离或意外而破裂的人际关系。

与《WILL：美好世界》中"神收到凡人信件"的设定类似，本作中玩家接收到的是来自 VRChat 用户的"聊天记录碎片"或"回忆片段"——这些片段被系统打乱，玩家需要将它们拖拽重组，改变事件的因果逻辑，让故事走向更好的结局。

**但本作与《WILL》的关键差异（差异化定位）：**

1. **修复不总是正确答案**。部分关卡的最优解是"接受分离"而非"强行挽回"。"Happy End"在本作中不等于"在一起"，而等于"关系被妥善地安放"。
2. **多角色共时叙事**。一个关卡内可同时存在 2–3 个角色的时间线，玩家可跨角色交换碎片，制造"蝴蝶效应"。
3. **元叙事闭环**。玩家扮演的"观测者"本身也是故事的一部分——第四章会揭示观测者的来历。

## 1.2 核心立意

VRChat 社交关系的独特之处在于：用户通过化身（Avatar）进行选择性自我呈现，在虚拟空间中获得了一种"比现实更近"的亲密感——友谊可以在短时间内迅速加深，而关系的断裂同样来得猝不及防。VRChat 社区中还存在一种被称为"砂糖"的独特关系形态——比朋友更亲密，但尚未成为情侣，这种关系的建立与消解往往伴随着微妙的情感拉扯。

本作希望以游戏化的方式，让玩家体验这种虚拟社交关系中的"修复"与"理解"。

**核心命题（贯穿全作）：**

> 当一段关系碎裂时，"修复"与"放手"，哪个才是温柔？

游戏不给出单一答案，而是让玩家在不同的排列组合中，亲眼看见两种选择的后果。

## 1.3 世界观与背景设定

### 1.3.1 「糖霜」

「糖霜（Sugar Frost）」是 VRChat 中一个**几乎无人访问的私人 World**。它由一位沉默的 World 制作者 **凛（Rin）** 独自搭建。世界不大：一片永远停在黄昏的雪原，雪原中央有一间亮着灯的玻璃房子，房子外的长椅上总是积着一层薄薄的雪。

凛给这个世界取名"糖霜"，源于她说过的唯一一句像样的话：

> "关系就像糖霜……甜的时候很甜。可一旦化了，就什么都不剩了。"

### 1.3.2 「回声服务器」

糖霜世界的地下（凛用 World 内不可见的 Trigger 区域搭建）藏着一台老旧的"回声服务器"。它会做一件事：

**把 VRChat 里散落的、未被妥善告别的关系碎片，整理成可以重新排列的"因果链"。**

在现实中，时间是线性的，一旦发生就无法更改。但在回声服务器里，事件的**顺序**是可以被重新排列的——而顺序变了，因果就变了，因果变了，结局就变了。

### 1.3.3 「观测者」

**玩家 = 观测者（Observer）。**

观测者没有 Avatar，没有名字，没有声音。他们能看见事件之间的**因果连线**——哪件事导致了哪件事，哪句话刺伤了谁。回声服务器选中观测者，是因为观测者拥有一种罕见的能力：

**"重新排列顺序而不引起逻辑崩塌"。**

**隐藏设定（第四章揭示）**：观测者并非神明，而是"曾经也失去过砂糖、且没能好好告别的人"的残响集合。每一个观测者，都对应着一个真实存在过的、破碎的关系。糖霜世界之所以存在，是因为凛在失去了一些东西之后，希望**总有人能替她完成她没能完成的事**——无论是修复，还是放手。

## 1.5 设计原则

1. **叙事服务于解谜**：所有文字表现、角色关系、氛围营造均为因果解谜服务。
2. **操作极简**：核心交互仅有"拖拽"和"点击"，降低上手门槛。
3. **情感驱动**：每一关的谜题背后，都是一个能让玩家产生情感共鸣的 VRChat 故事。
4. **无惩罚探索**：任何排列都不会"失败"，只会导向不同的结局；鼓励玩家试错。
5. **文字克制**：不煽情、不文学腔，用 VRChat 用户真实的日常语感说话。

## 1.7 情感基调与分级

- 全年龄友好，无成人内容、无恐怖惊吓。
- 含轻度情感失落主题（疏离、被冷落、告别），建议 12+。
- 不含任何真实用户、社团或 UGC 内容的直接影射。

# 二、核心玩法机制

## 2.1 主循环

```
接收碎片 → 阅读碎片 → 拖拽重组 → 因果推演 → 结局判定 → 解锁新碎片
     ↑                                                        │
     └──────────────── 存档 / 图鉴 / 提示 ←────────────────────┘
```

**单关流程（详细）：**

1. **进入关卡**：全屏淡入，显示关卡标题、涉及角色、一句话情境。
2. **阅读碎片**：碎片以卡片形式散列在工作区，玩家可悬停/点击查看完整文本。
3. **拖拽重组**：玩家拖拽白色/金色/红色碎片到因果链的槽位中。
4. **因果推演**：每次落位后，系统进行**快速预判**，用两根进度条显示"因果连贯度 / 情感走向"。
5. **提交判定**：玩家点击"让因果稳定"按钮（或拖拽后自动触发）。
6. **结局展示**：全屏淡入对应色调，显示结局名、类型、结局文本。
7. **结算**：显示"保留此结局 / 继续排列"，并解锁新碎片或新关卡。

## 2.2 碎片系统

### 2.2.1 碎片类型与规则

| 碎片类型 | 视觉 | 说明 | 可拖拽 | 备注 |
|---|---|---|---|---|
| **白色碎片** | 纸白卡片 | 普通事件，可自由调整顺序 | ✅ | 核心可操作元素 |
| **灰色碎片** | 灰度卡片 + 锁形角标 | 固定事件，不可移动 | ❌ | 作为因果锚点（起点/终点） |
| **金色碎片** | 金色描边 + 微光 | 关键事件，移动后触发特殊效果 | ✅ | 如交换两人对话、触发隐藏分支 |
| **红色碎片** | 暗红描边 + 裂纹 | 负面事件，需被"覆盖"或"移到末位" | 有条件 | 部分关卡中可被金色碎片替换 |
| **蓝色碎片（V2新增）** | 冷蓝描边 + 水波纹 | 内心独白/未说出口的话，不入主链，仅作氛围提示 | ❌ | 随关卡进度解锁，提供情感线索 |

### 2.2.2 碎片文本规范

- 每段碎片控制在 **20–60 字**。
- 以**动作描述**为主，**对话**为辅。
- 避免过于文学化的表达，保持 VRChat 用户日常交流的自然感。
- 统一使用**角色名/ID**指代，不出现"玩家"以外的第二人称。
- 示例：
  - ✅「他在 World 列表里翻了好久，最后停在那个两人一起去过的星空房间。」
  - ❌「他悲痛欲绝地搜寻着往昔的残影。」（过度文学化）

### 2.2.3 碎片数据结构

```json
{
  "id": "frag_2_3_05",
  "levelId": "2-3",
  "type": "white",
  "character": "A",
  "text": "A在B的好友列表中发现陌生ID",
  "tags": ["discovery", "jealousy"],
  "unlockedBy": null,
  "note": "情感线索：这里第一次出现'第三方'的阴影"
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一标识，格式 `frag_<章节>_<关卡>_<序号>` |
| `levelId` | string | 所属关卡 |
| `type` | enum | `white` / `gray` / `gold` / `red` / `blue` |
| `character` | enum | `Mio` / `Shiori` / `Rin` / `Yu` / `Observer` / `null`（旁白） |
| `text` | string | 碎片正文（20–60 字） |
| `tags` | string[] | 语义标签，用于预判动画与提示系统 |
| `unlockedBy` | string \| null | 若为隐藏碎片，记录解锁条件（见 2.7） |
| `note` | string | 设计备注，不展示给玩家 |

## 2.3 拖拽规则与约束

- **规则 1（锚点）**：碎片不可被移动到序列的最前端或最末端——首尾由灰色锚点碎片固定，确保每个故事有确定的起点与终点。
- **规则 2（灰色锁定）**：灰色碎片在拖拽开始时显示禁用样式（降低透明度 + 禁止光标），无法被拾起。
- **规则 3（红色约束）**：红色碎片默认不可拖拽，但若关卡中存在金色碎片且满足特定条件（如"金色碎片被放到红色碎片之前"），红色碎片会被"净化"为白色并解锁拖拽。
- **规则 4（跨角色）**：当关卡存在多条角色时间线时，允许将 A 线碎片拖入 B 线槽位，触发蝴蝶效应（见 2.5）。
- **规则 5（槽位数）**：单关卡槽位数 = 碎片总数，固定为 6–9 个（含锚点）。

## 2.4 因果重组判定引擎

### 2.4.1 问题定义

碎片排列组合数量随碎片数呈**阶乘级**上升（8 个可动碎片 = 40320 种）。为可控地映射到有限结局，采用 **"约束评分 + 结局映射表"** 方案：

> 每个结局定义一组**加权因果约束**；系统对当前序列逐条打分，取得分最高且超过阈值的结局；若均不达标，则落入"混沌结局（未探索）"。

### 2.4.2 约束类型

| 约束种类 | 语义 | 示例 |
|---|---|---|
| `before` | A 必须排在 B 之前 | `碎片3` 在 `碎片2` 之前 → 先关心，后看见 |
| `adjacent` | A 与 B 必须相邻（顺序敏感） | `伸手` 紧邻 `握住` |
| `position` | 某碎片必须落在第 N 个槽位 | `犹豫` 必须排在第 1 位 |
| `block` | A 与 B 不可相邻 | 防止逻辑断裂 |
| `group` | A、B 必须同属某连续区间 | 一段回忆必须聚在一起 |
| `anti` | 违反则扣分（负权重） | 若"退出"排在"邀请"前 → 扣分 |

### 2.4.3 评分公式

```
Score(ending) = Σ_satisfied(weight) − Σ_violated(penalty)
若 Score ≥ ending.threshold → 该结局可命中
命中集合中取 Score 最高者；并列时取 constraintCount 更少者（更"顺其自然"的解法）
若无命中 → 触发「混沌结局（未探索）」
```

同时向玩家展示两个派生指标（用于预判进度条）：

- **因果连贯度 Coherence** = Score / Score_max（归一化到 0–100）
- **情感走向 Valence** = Σ(命中碎片的 valence 权重)，负值偏"疏离"，正值偏"靠近"

### 2.4.4 判定伪代码

```js
function judge(sequence, level) {
  const results = level.endings.map(e => ({
    ending: e,
    score: scoreEnding(sequence, e),
  }));

  const qualified = results
    .filter(r => r.score >= r.ending.threshold)
    .sort((a, b) =>
      b.score - a.score ||
      a.ending.constraints.length - b.ending.constraints.length
    );

  if (qualified.length === 0) {
    return { ending: level.chaosEnding, isChaos: true };
  }
  return { ending: qualified[0].ending, isChaos: false };
}

function scoreEnding(seq, ending) {
  let s = 0;
  for (const c of ending.constraints) {
    if (matchConstraint(seq, c)) s += c.weight;
  }
  for (const a of ending.anti) {
    if (matchConstraint(seq, a)) s -= a.penalty;
  }
  return s;
}
```

## 2.5 蝴蝶效应系统

当一关中存在多个角色的故事线时，玩家可以跨角色交换碎片。例如：

> 角色 A 的碎片"独自在空城徘徊"与角色 B 的碎片"在人群中寻找 A"交换位置后，两人的故事线会在新的时间点交汇，触发隐藏剧情。

**触发条件：**
1. 关卡标记 `hasButterfly: true`；
2. 某跨角色交换使两条时间线在时间轴上"相遇"（即 A 线某碎片与 B 线某碎片相邻）；
3. 相遇点的 `tags` 存在语义关联（如 `search` ↔ `waiting`）。

**触发效果：**
- 解锁 **蓝色碎片**（内心独白）1–2 条；
- 显示一段额外的"交汇演出"文本；
- 若满足全局条件，登记到**蝴蝶效应图鉴**。

**示例（关卡 3-3「人群中的陌生人」）：**
- 澪的碎片「澪站在人群外，看着栞和悠笑」与悠的碎片「悠指着澪的方向问：那个人是朋友吗？」交换相邻后触发隐藏剧情——**栞其实一直在找澪**。

## 2.6 结局系统

### 2.6.1 结局分类

| 类型 | 标识 | 色彩 | 定义 |
|---|---|---|---|
| **修复结局** | `good` | 暖金渐变 | 关系得到改善、维系，或**被妥善地放下** |
| **遗憾结局** | `bittersweet` | 灰蓝渐变 | 关系走向改变但并非完美，如"砂糖"关系的自然消解 |
| **破碎结局** | `bad` | 暗红渐变 | 关系进一步恶化 |
| **混沌结局** | `chaos` | 静态噪点 | 未探索的组合，无有效因果，仅作兜底 |
| **隐藏结局** | `true` | 双层光晕 | 达成特定跨关条件后解锁的"真相结局" |

### 2.6.2 结局判定原则

- 结局判定基于碎片序列的**逻辑一致性评分**，而非简单的"正确/错误"二分。
- 每关 **3–5 种结局**，鼓励玩家探索多种排列组合。
- 任何一个结局都会**永久记入结局图鉴**。
- "修复结局"不必然等价于"Happy End"——例如关卡 3-2 的最优解可能是"体面地告别"。

## 2.7 提示与解锁系统

### 2.7.1 渐进式提示

| 卡关时长/次数 | 提示层级 | 内容 |
|---|---|---|
| 3 次未通关 | L1 方向性提示 | "注意两句话之间的时间关系"（不点破具体碎片） |
| 6 次未通关 | L2 高亮提示 | 高亮一对待调整顺序的碎片 |
| 10 次未通关 | L3 直接提示 | 展示推荐序列的前两步 |
| 主动点击"?" | 随时 | 仅显示当前关卡涉及的因果规则说明 |

> 设计原则：**首次卡关时给出方向性引导，而非直接答案。** 提示使用次数计入"完美通关"评价。

### 2.7.2 碎片解锁机制

- 通关任一结局 → 解锁下一关卡。
- 首次达成某类型结局（good/bittersweet/bad） → 解锁 1 条蓝色碎片（内心独白）。
- 集齐某关卡的全部结局 → 解锁该关卡"幕后注释"（作者设计说明）。
- 触发蝴蝶效应 → 解锁跨关卡隐藏碎片。

## 2.8 情感羁绊系统（V2 新增）

每个主要角色拥有一条隐藏的**羁绊值（Bond）**，范围 `-100 ~ +100`。

- 每关的结局会按 `valence` 影响相关角色的羁绊值；
- 羁绊值不直接决定结局，但会影响：
  - 第四章的可用碎片池（羁绊高的角色会主动"说出"更多内心独白）；
  - 全局结局的判定（见 §5.3）；
  - 图鉴中角色档案的"最终状态"文案。

| 羁绊值区间 | 状态 | 表现 |
|---|---|---|
| +60 ~ +100 | 亲密 | 角色档案显示温暖的最终回忆 |
| +20 ~ +59 | 友好 | 关系稳定 |
| -19 ~ +19 | 疏离 | 中性结局 |
| -20 ~ -59 | 冷淡 | 部分回忆被"雾化" |
| -60 ~ -100 | 断裂 | 角色档案显示"已注销" |

## 5.3 全局结局判定

全局结局在终章 4-3 结算时计算，参与变量：

|---|---|---|

| `trueCount` | 全作达成的隐藏结局数 | 0.2 |
| `bond.Mio / .Shiori / .Rin` | 三名角色羁绊值均值 | 0.2 |

```
GlobalScore = 0.4*levelScore(4-3)
            + 0.2*(goodCount / 9) * 100
            + 0.2*(trueCount / 10) * 100
            + 0.2*mean(bond)

GlobalScore ≥ 85 → 真结局「欢迎回来」
GlobalScore ≥ 65 → Happy End「重新开始」
GlobalScore ≥ 40 → Bittersweet End「远处的灯」
GlobalScore < 40 → Bad End「无人登入」
特殊：满足"放手"条件 → 隐藏结局「把世界交给你」（优先级高于真结局）
```

## 5.4 二周目与"回声模式"（P2 扩展）

- 一周目通关后开放**回声模式**：所有关卡可自由重玩，并显示**上一次的解**作为对照。
- 回声模式下解锁**观测者注释**：每条碎片旁标注"这句话原本在谁嘴里"。
- 全结局收集后解锁**凛的留言**：一段关于糖霜世界建造初衷的最终独白。

## 6.2 拖拽交互详细需求

- **拖拽方式**：HTML5 Drag and Drop API，桌面端支持鼠标拖拽，移动端支持触摸拖拽（统一走 Pointer Events）。
- **卡片布局**：碎片卡片高度自适应文本长度；单列纵向链条为主，跨角色时切换为并列双列。
- **拖拽表现**：被拖拽碎片半透明（`opacity: .6`）跟随光标/手指，`transform: scale(1.02)`，投影加深。
- **插入指示**：目标位置显示 2px 高的插入指示线（角色主色）。
- **释放反馈**：释放后自动重排布局，卡片带 180ms 的"落定"缓动。
- **禁用样式**：不可拖拽的碎片（灰色/未解锁红色）在拖拽开始时降低透明度 + 显示禁止光标。
- **自动预判**：拖拽结束后，若序列发生变化，自动触发结局预判动画（§6.3）。
- **键盘无障碍**：支持 Tab 聚焦 + `Ctrl/⌘ + ↑/↓` 移动碎片；`Enter` 确认落位。
- **撤销**：`Ctrl/⌘ + Z` 撤销上一步（保留 20 步历史）。

## 6.3 结局预判与反馈

- 每次拖拽操作完成后，系统对当前序列进行**快速逻辑评估**。
- 若序列为**已解锁的结局组合**，显示对应结局预览（文字摘要 + 情感色调）。
- 若序列为**未探索组合**，显示"因果稳定中……"的过渡状态，**2 秒后**展示结局。
- 结局展示后，提供 **"保留此结局"** 或 **"重新排列"** 选项。
- 顶部常驻两根指标条：
  - **因果连贯度 Coherence**（0–100，冷蓝色）
  - **情感走向 Valence**（-100 ~ +100，暖→冷渐变）

## 6.4 存档系统

- **存储介质**：LocalStorage（进度、设置、羁绊值）+ IndexedDB（已见碎片文本、结局快照）。
- **存档内容**：
  - 已通关关卡与当前关卡；
  - 已解锁/已达成结局 ID 集合；
  - 各角色羁绊值；
  - 设置（音量、字号、减少动效、色盲模式）；
  - 提示使用次数。
- **保存时机**：每次结局判定后、每次离开关卡时、每 30 秒自动保存。
- **容错**：版本号检测，数据结构升级时执行迁移；解析失败则备份原数据并重置为新档。
- **多档位**：支持 3 个存档槽 + 1 个自动存档。

```json
{
  "version": 2,
  "slots": [
    {
      "id": 1,
      "updatedAt": 1726000000000,
      "progress": { "currentLevel": "2-3", "cleared": ["1-1","1-2","1-3","2-1","2-2"] },
      "endingsSeen": ["1_1_good", "1_1_bad", "2_1_good"],
      "bond": { "Mio": 35, "Shiori": 40, "Rin": -10 },
      "hintsUsed": 2,
      "settings": { "volume": 0.6, "reduceMotion": false, "colorBlind": false }

```

# 八、视觉与氛围设计

## 8.1 视觉风格

- **整体基调**：低饱和度的冷色调为主，辅以暖色点缀，呼应 VRChat 夜晚世界的氛围。
- **背景**：深蓝到墨黑的径向渐变，叠加极淡的雪花粒子（CSS 动画，可关闭）。
- **碎片卡片**：类似纸质卡片的质感，带轻微噪点纹理（noise texture，`opacity: .04`）。
- **拖拽反馈**：碎片被拿起时投射柔和阴影，释放时卡片有轻微的"落定"动画。
- **结局展示**：全屏淡入淡出，配以对应结局色调的渐变背景。

## 8.2 结局色调规范

| 类型 | 渐变 | 主色 |
|---|---|---|
| `good` | 暖金 → 米白 | `#F5D9A8` → `#FBF6EE` |
| `bittersweet` | 灰蓝 → 雾白 | `#9FB3C8` → `#EEF2F5` |
| `bad` | 暗红 → 深灰 | `#7A3B3B` → `#2A2A2E` |
| `true` | 双层光晕（暖金 + 冷蓝叠加） | `#F5D9A8` + `#A8C4DD` |
| `chaos` | 静态噪点 + 扫描线 | `#3A3A3E` |

# 十二、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 排列组合数量爆炸导致结局设计困难 | 高 | 采用约束评分法，将组合归纳为有限类别；控制单关卡碎片数 ≤ 9（可动 ≤ 7） |
| 纯前端拖拽在移动端体验不佳 | 中 | 优先保证桌面端体验，移动端作为 P1 适配，使用 Pointer Events 统一处理 |
| VRChat 文化圈层较窄，受众有限 | 中 | 通过情感共鸣（友情、失落、释怀）拓展非 VRChat 用户；名词表内联解释 |
| 因果逻辑不够直观，玩家卡关 | 中 | 提供渐进式提示系统，首次卡关时给出方向性引导而非直接答案 |
| 多结局设计导致玩家"穷举"而非"理解" | 中 | 结局语义区分度设计（同类型结局文本差异大）；预判指标条引导玩家思考因果而非试错 |
| 第四章元叙事反转过于突兀 | 中 | 前三章埋设蓝色碎片与凛的伏笔；4-1 用"回声"而非"说明"完成揭示 |
| 文案量过大导致本地化困难 | 低 | 全部文案走 i18n key，碎片正文与结局文本分离存储 |

# 十三、验收标准

1. 玩家可在桌面浏览器中完成**至少 12 个关卡**的因果重组解谜。
2. 每个关卡至少包含 **3 种可解锁结局**（本作实际为 3–4 种，关卡内共 45 个，另加 5 个全局结局，合计 62 个结局条目）。
3. 拖拽交互流畅，无卡顿或误触（拖拽响应 < 50 ms）。
4. 游戏进度在刷新页面后可恢复。
5. 核心玩法在**不阅读任何教学文本**的情况下，通过第一个教学关卡（1-1）即可理解。
6. 判定引擎单元测试分支覆盖 ≥ 90%，且 2-3 的基准用例（§4.2.3）结果与设计一致。
7. 至少存在 **1 个"最优解是放手"的关卡**（3-2），且该设计对玩家可感知。
8. 全作存在 **Happy End 与 Bad End 各至少 1 个**，且全局结局由羁绊值/结局数共同决定。
9. 移动端（P1）可完成至少第一章全部关卡。
10. 无障碍：键盘可完成全部核心操作；色盲模式下角色可区分。
