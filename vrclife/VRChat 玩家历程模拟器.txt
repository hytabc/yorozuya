VRChat 玩家历程模拟器 需求设计 PRD v0.2

1. 项目概述

做一个以 VRChat 游戏时长（小时） 为主轴的玩家历程模拟器。玩家从萌新进入 VRChat，经历探索、社交、学习、情感关系（尤其是“砂糖”关系）、低迷、回归、新关系等循环，最终根据累计小时数和关键选择生成人生总结。

核心目标：

· 用 小时数 代替年龄，如 10h、23h、158h、500h、1000h。
· 流程高度随机：事件池 + 条件过滤 + 权重随机 + 结果随机。
· 体现 VRChat 特有文化：Avatar、World、中文吧、贴贴、砂糖、模型、跳舞、摄影、语言交换、社区活动。
· 重点模拟“砂糖”关系的接触 → 成为砂糖 → 美好 → 结束 → 低迷 → 新朋友 → 新思考 → 新砂糖的循环。
· 单局 5-15 分钟，可重开，可复现（随机种子）。

---

2. 核心玩法

2.1 核心循环

开始 → 随机生成初始状态（萌新、无好友、基础模型）→ 按小时推进 → 触发事件 → 玩家选择 → 随机结果 → 属性/关系/标签变化 → 累计小时增加 → 判断是否进入下一阶段或结局。

2.2 时间推进：以小时为单位

· 初始：0h，萌新。
· 每回合随机推进 1-20h，关键节点可强制推进到特定小时。
· 里程碑参考：
  · 0-10h：初入 VRChat
  · 10-50h：萌新探索
  · 50-200h：社交起步
  · 200-500h：深度社交与砂糖期
  · 500-1000h：老油条/社区名人
  · 1000h+：传奇/退坑边缘
· 更细分示例：23h、158h、213h 均可由随机步长自然产生。

2.3 示例流程

10h：你第一次进入 VRChat，笨拙地加载了一个默认模型。有人用中文问你：“萌新？”
选项：跟着他 / 自己探索 / 去中文吧
你选择：跟着他。
结果：你加到了第一个好友，学会基础操作。好友 +1，心态 +5。

23h：你开始频繁去中文吧，认识了几个人。有人邀你一起跳舞。
选项：加入 / 旁观 / 去学模型
你选择：加入。
结果：你学会了简单舞蹈，圈子 +1，魅力 +2。

158h：你和一个人经常一起玩，互相叫“砂糖”。今晚他/她送你一个模型。
选项：表白 / 保持现状 / 回赠礼物
你选择：表白。
结果：你们成为正式砂糖。亲密度 +20，心态 +15，标签“砂糖中”。

213h：砂糖关系因为现实忙碌出现裂痕。
选项：挽留 / 冷静 / 主动结束
你选择：主动结束。
结果：你进入低迷期。心态 -30，标签“失恋”，事件权重偏向孤独。

500h：你已成为社区小有名气的摄影师，遇到新朋友。
选项：敞开心扉 / 保持距离 / 只谈VRChat
你选择：敞开心扉。
结果：你开始新的思考，逐渐走出低迷。

1000h：你回顾这段虚拟人生。

3. 状态系统

3.1 基础属性

· 累计时长：小时数，核心进度。
· 好友数量：0-999。
· 社交圈子：中文吧、跳舞圈、模型圈、摄影圈、游戏圈、语言交换等。
· 技能：建模、编程、摄影、音乐、舞蹈、语言、社交、整活。
· 心态：好奇、热情、疲惫、低迷、佛系、退坑边缘。
· 声望：默默无闻、小有名气、社区名人、传奇。
· 资产：模型数量、道具、世界收藏、VRChat+ 订阅。
· 情感状态：单身、暧昧、砂糖中、失恋、怀念、新砂糖。

3.2 标签系统

· 状态标签：萌新、社恐、话痨、模型师、摄影师、舞者、翻译、夜猫子、砂糖中、失恋、退坑边缘、回归者。
· 标签影响事件触发和选项可用性。

---

4. 砂糖关系系统（核心）

4.1 关系状态机

陌生人 → 认识 → 朋友 → 常一起玩 → 暧昧 → 砂糖 → 稳定/矛盾 → 结束 → 低迷 → 恢复 → 新朋友 → 新砂糖

4.2 关系属性

· 亲密度：0-100。
· 依赖度：0-100。
· 信任：0-100。
· 新鲜感：0-100，随时间下降。
· 现实压力：0-100，影响结束概率。

4.3 关键事件

· 接触：在中文吧、活动、世界遇到某人。
· 成为砂糖：一方或双方提出，或自然形成。
· 美好过程：一起看风景、拍照、跳舞、做模型、跨年、贴贴。
· 结束：现实忙碌、性格不合、第三者、误解、退坑、一方找到现实伴侣。
· 低迷期：心态下降，事件池偏向孤独、回忆、退坑。
· 新朋友：低迷期后遇到愿意陪伴的人。
· 新思考：获得感悟标签，影响后续选择。
· 新砂糖：循环再次开始。

4.4 随机性

· 每次砂糖关系的结果不固定：可能长久，可能短暂，可能转为朋友。
· 结束原因随机，低迷时长随机。
· 新砂糖出现的时间、对象、方式随机。

---

5. 事件系统

5.1 事件字段

· id、标题、文案模板。
· 小时范围、阶段。
· 触发条件：属性、标签、前置事件、排除标签。
· 权重、稀有度。
· 一次性、冷却。
· 选项列表。
· 每个选项的随机结果。

5.2 事件类型

· 普通事件：随机抽取。
· 关键事件：达到小时数强制触发，如第一次加好友、第一次砂糖、第一次失恋。
· 随机事件：中奖、被送模型、遇到名人、服务器崩溃。
· 保底事件：无可用事件时触发，如“你独自逛了几个世界”。
· 连锁事件：选择后安排未来事件。

5.3 选项与结果

每个事件 2-4 个选项。
选项可有条件显示，如“表白”需要亲密度 > 60。
每个选项 1-3 个结果，按权重随机：

· 70% 普通结果
· 20% 稀有结果
· 10% 极端结果

结果影响属性、标签、关系、未来事件。

---

6. 随机机制

1. 随机种子：每局生成 seed，所有随机基于 seed。
2. 事件池抽取：过滤可用事件后加权随机。
3. 权重动态计算：基础权重 × 阶段修正 × 属性修正 × 标签修正 × 冷却惩罚 × 随机扰动。
4. 结果随机：同一选择也可能有不同结果。
5. 小时步长随机：每次推进 1-20h。
6. 文案变量：如“在{中文吧|跳舞房|私人世界}遇到”。
7. 导演系统：连续负面后提升正面事件权重，避免一直低迷。
8. 防重复：最近事件冷却，一次性事件用后移除。
9. 稀有事件：低概率高影响，如遇到 VRChat 名人、模型被疯狂点赞、成为社区传奇。

伪代码：

```js
function pickEvent(state, rng) {
  const pool = EVENTS.filter(e => match(e, state) && !state.used.has(e.id));
  const scored = pool.map(e => {
    let w = e.weight;
    w *= stageWeight(e.stage, state);
    w *= attrMod(e, state);
    w *= tagMod(e, state);
    w *= cooldownMod(e, state);
    w *= 0.8 + rng() * 0.4;
    if (state.lastEventTags.some(t => e.tags.includes(t))) w *= 0.3;
    return { e, w };
  });
  return weightedRandom(scored, rng);
}

function choose(state, event, option, rng) {
  const outcome = weightedRandom(option.outcomes, rng);
  applyEffects(state, outcome.effects);
  state.hours += randInt(1, 20, rng);
  state.history.push({ hours: state.hours, event, option, outcome });
  state.used.add(event.id);
  nextTurn(state);
}
```

7. 结局系统

触发：

· 累计小时达到 1000h、5000h 或玩家主动结束。
· 心态归零（退坑）。
· 特定标签，如“传奇”“砂糖无数”“孤独终老”。

结局根据总时长、好友数、砂糖次数、技能、心态、声望生成。
示例：

· VRChat 传奇
· 退坑回归现实
· 砂糖循环者
· 孤独探索者
· 社区领袖
· 模型大师
· 永远萌新
· 佛系养老

展示：结局称号、人生总结、关键选择、属性雷达图、重开/分享。

8. 页面交互

· 顶部：当前小时数、阶段、随机种子。
· 左侧：属性面板（好友、心态、情感、技能、声望）。
· 中间：时间线，显示历史事件与选择。
· 底部：当前事件卡、选项按钮。
· 选择后：结果弹层，属性变化浮动。
· 结局页：卡片 + 雷达图 + 时间线回放。
· 风格：VRChat 界面风、霓虹、像素、手账均可。

10. 内容设计规范

· MVP 至少 150 个事件，覆盖 0-1000h。
· 每个小时段至少 15-20 个事件。
· 每个事件 2-4 个选项，每个选项 1-3 个结果。
· 文案短，单屏可读完。
· 避免真实人物、敏感政治。
· 砂糖关系事件至少 30 个，覆盖接触、美好、矛盾、结束、低迷、新朋友、新砂糖。
· 关键节点：第一次加好友、第一次去中文吧、第一次学模型、第一次砂糖、第一次失恋、第一次退坑、第一次回归、1000h 总结。

11. 技术方案建议

· 前端：React + TypeScript + Vite。
· 状态管理：Zustand。

12. MVP 与迭代

MVP

· 开始页、随机萌新出身。
· 小时推进、事件池、选项、随机结果。
· 好友、心态、情感、砂糖关系。
· 时间线、结局、重开。
· 150 个事件、10 个结局。

第二阶段

· 天赋、成就、图鉴。
· 分享卡片、随机种子。
· 更多事件、音效、动画。
· 导演系统动态权重。

第三阶段

· 账号、云存档。
· UGC 事件编辑器。
· AI 生成事件文案。
· 排行榜、多人对比。

---

13. 验收标准

· 每局至少 30 个事件。
· 至少 10 种结局。
· 同一 seed + 同一选择，结果可复现。
· 无满足条件事件时，能自动触发保底事件。
· 属性、小时数、标签变化正确。
· 砂糖关系循环至少能完整走通一次。
· 移动端可正常操作。
· 单局无致命报错。
