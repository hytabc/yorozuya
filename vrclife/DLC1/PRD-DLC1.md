# VRChat 玩家历程模拟器 · DLC1 设计文档

**版本**：DLC1 v1.0
**基线**：主 PRD v1.0 / SCHEMA.md v1.0（数据契约不变，DLC 只做**加法**）
**状态**：可直接进入开发

---

## 0. 这个 DLC 是什么

DLC1 给本体加三样东西：

1. **设备维度**——把「用什么玩 VRChat」变成一条贯穿全程的支线：Pico / Quest / PCVR、串流、全身追踪（Tracker / SlimeVR）、面捕、晕动症、幻肢、掉追。
2. **友情的第二层**——本体只有「砂糖关系」（恋爱向、唯一、有状态机）。DLC1 补上**圈子冲突**与**朋友的情绪**：加入新圈子会得罪旧圈子、朋友会闹情绪、你要不要帮朋友解决现实困难。
3. **好感度系统**——本体只统计「好友数量」。DLC1 增加一个 0-100 的 `favor`（好感度），衡量你与「当前最亲近的那位朋友」的交情，并由此派生新的标签与结局。

外加 **7 个新结局**、**4 个新出生**、**3 个新圈子**、**一批设备术语词表**与 **59 个新事件**。

> 设计原则与本体一致：**不评判**（Pico 是 Pico，Quest 是 Quest，没有高低）、**不鸡汤**、**有画面**、**有痛感**。
> DLC1 尤其遵守本体的「设备平等」：所有设备差异只影响**体验与事件走向**，不写成优劣。

## 1. 设备设定（Pico / Tracker / 串流）

### 1.1 设备类型

| 代号 | 中文 | 特点（用于事件与文案） |
|---|---|---|
| `quest` | Quest | 一体机，无线、便携、画质与性能受限、生态封闭 |
| `pico` | Pico | 一体机，国内用户多、需要折腾串流、手柄与追踪手感不同 |
| `pcvr` | PCVR | 需要 PC 与基站，画质最好，但被线缆和房间绑住 |
| `fbt` | 全身追踪 | Tracker / SlimeVR / HaritoraX，脚腰能动了，但要校准、会掉追 |
| `face` | 面捕 | 表情能同步了，但设备贵、嘴追会飘 |

### 1.2 关键术语（进入受控词表，见 `vocab.dlc1.json`）

轻量设备：一体机、串流、VD（Virtual Desktop）、Air Link、有线串流、无线串流、基站、手柄漂移、掉帧。
追踪：Tracker、SlimeVR、HaritoraX、FBT、脚追、腰追、6 点、11 点、校准、掉追、踩点、动捕。
面捕：面捕、嘴追、眼追、表情、幻肢。
身体体验：晕动症、VR 晕、晕车、体温、汗、颈椎。

> 以上术语不是装饰。**每一条都必须至少出现在一个事件的正文或选项中**，否则视为未落地的设定。
> 校验脚本 `validate_dlc1.py` 会统计术语覆盖率。

### 1.3 设备支线的结构

```
device_k01 开箱（0-40h）
   ├─ 选 Quest  → tag「Quest党」＋「设备党」
   ├─ 选 Pico   → tag「Pico党」＋「设备党」
   └─ 选 PCVR   → tag「串流党」＋ skill.coding +3
        ↓
device_k02 第一次全身追踪（150-400h）
   ├─ 上追踪   → tag「全身追踪」＋ flag owns_fbt，dance 成长加速，但解锁「掉追」事件
   ├─ 只用手柄 → 保持原样，解锁「旁观别人的脚」文案线
   └─ 先云一下 → 不买设备，assets 保留，解锁「试模狂魔」倾向
```

设备事件为**全阶段低权重随机**，但带有设备标签时权重 ×1.5（见 §5 权重修正）。
**不设专属结局门槛**——设备只是体验差异，进不进结局看玩家怎么用。

## 2. 好感度系统（Favor）

### 2.1 为什么需要它

本体里 `friends` 只是一个数字：涨了不知道因为谁，掉了不知道伤了谁。
DLC1 增加 `favor`（0-100），代表**你与当前最亲近的那位朋友之间的交情**。
它和 `mood`、`fame` 同级——是一个全局标量，不是关系状态机。

### 2.2 档位

| favor | 档位 | 含义 |
|---|---|---|
| 0-19 | 生分 | 只是列表里的一个名字 |
| 20-39 | 客套 | 见面点个头，聊两句天气 |
| 40-59 | 聊得来 | 会主动找对方，会说点真心话 |
| 60-79 | 交心 | 有事第一个想到 ta |
| 80-100 | 挚友 | 你们不需要解释 |

### 2.3 规则

- **自然漂移**：每回合 `favor -0.35`（不互动就会淡）。这是唯一一条「无事件也变化」的规则，用来对抗「好友列表越长、交情越薄」。
- **事件驱动**：`effects.favor` 增减。真心帮忙 +6~12，敷衍 -4~-8，背叛 -20。
- **自动标签**：
  - `挚友`：`favor ≥ 80` 时添加，`favor < 60` 时移除。
  - `圈子浪人`：`circles.length ≥ 5` 时添加（朋友很多，但没有一个深交）。
- **条件**：事件/选项可用 `minFavor` / `maxFavor` 做门槛。例如「向 ta 说真话」需要 `minFavor: 60`。
- **结局计分**：`favor` 进入 `endings.json` 的 `scoring.vars`，作为 `end_best_friend`、`end_circle_hopper` 等新结局的判据。

> **与砂糖关系的关系**：`favor` 描述**友情**，`relation` 描述**恋爱/砂糖**。两者独立。
> 一个高 favor 的朋友可以完全不是砂糖；一个砂糖对象也可能在 `favor` 上并不高（你们只有彼此，却没有交情）。这正是一些新结局想说的东西。

### 2.4 状态扩展（引擎需增量支持）

```jsonc
// GameState 新增字段
{
  "favor": 50,                  // 好感度 0-100，初始 50（陌生的善意）
  "counters": {
    "favorGained": 0,           // 累计获得的好感度
    "favorLost": 0,             // 累计失去的好感度
    "friendsHelped": 0,         // 帮朋友解决困难的次数
    "feudsResolved": 0          // 调解圈子/朋友矛盾的次数
  }
}
```

## 3. 圈子冲突系统

### 3.1 新圈子

| 圈子 | 获取途径 | 解锁事件倾向 |
|---|---|---|
| 设备圈 | 开箱事件选择任一设备，或 `coding ≥ 15` | 硬件、装机、串流、踩坑 |
| 追踪圈 | `全身追踪` 标签 或 `dance ≥ 25` | 掉追、校准、双人舞 |
| 面捕圈 | 面捕事件选择留下 | 表情、嘴追、演绎 |

### 3.2 冲突机制（不加引擎状态，纯数据驱动）

圈子冲突**不引入新的全局开关**，而是用**标签 + 权重**表达：

1. **站队标签**：`circle_k02` 让玩家在两个圈子间站队，写入 flag（如 `stood_with_dance` / `stood_with_model`）。
2. **发酵事件**：站队后 `schedule` 一个「另一方的不满」事件，用 `requireFlags` / `excludeFlags` 区分走向。
3. **代价**：站队给一边 `favor +`，同时给 `friends -` 或 `fame -`。**没有两边都不得罪还能全拿的选项**——这是设计意图。
4. **调解路线**：`social` 够高时解锁「把两边叫到一起」的选项，成功则 `feudsResolved +1`，指向 `end_mediator`。

> 圈子冲突不是「坏人做坏事」，而是**两群都对的人无法共处**。文案不指责任何一方。

## 4. 朋友情绪与求助系统

### 4.1 三种朋友事件

| 类型 | 触发 | 玩家能做什么 |
|---|---|---|
| **闹情绪** | 全阶段随机 | 倾听 / 讲道理 / 躲开。倾听涨 favor 但耗 mood，讲道理可能更糟 |
| **求助** | 深度社交+，`friends ≥ 10` | 帮（掉 assets / hours，涨 favor、解锁 flag）/ 拒绝（掉 favor，涨 mood） |
| **冲突** | `circle_k02` 连锁 | 站队 / 调解 / 装没看见 |

### 4.2 设计约束

- **帮朋友一定有代价**：钱、时间、心情，至少掉一样。**免费的好事不叫帮忙。**
- **拒绝不是罪**：拒绝的文案保持中性，且 `mood +`（你保护了自己）。但 favor 会掉。
- **不写「你救了 ta」**：朋友的问题不会因为一次帮助就彻底解决。最多是「那一晚 ta 没那么难受」。

## 5. 权重修正（DLC 追加）

在 `scoreEvent` 的修正链（PRD §6.2）末尾追加：

```ts
// 设备修正：带了对应设备标签，该设备线事件权重 ×1.5
if (e.tags.includes('设备') && hasAnyDeviceTag(state)) w *= 1.5;

// 圈子修正：事件要求玩家已加入的圈子，权重 ×1.3（本体已有，DLC 复用）
// 好感度修正：挚友在场时，友情类「正面」事件权重 ×1.4
if (state.tags.includes('挚友') && hasTag(e, '友情') && hasTag(e, '正面')) w *= 1.4;

// 孤独修正：favor 很低时，「友情」类事件权重 ×1.3（越缺越遇到）
if (state.favor < 30 && hasTag(e, '友情')) w *= 1.3;
```

## 6. 新结局（7 个）

在 `endings.dlc1.json` 中定义，`scoring.vars` 追加 `favor`。

| id | 称号 | 优先级 | 触发要点 | 想说的话 |
|---|---|---|---|---|
| `end_mediator` | **圈子里的调解人** | 74 | 400h+、friends ≥ 45、social ≥ 36、`resolved_feud` | 你不属于任何一边，但两边都信你 |
| `end_best_friend` | **有人叫你挚友** | 72 | 300h+、favor ≥ 80、friends ≥ 20 | 好友列表很长，但你只对一个人好 |
| `end_reunion` | **多年后的一句最近好吗** | 68 | 700h+、`got_reunion_message` | 有些人只是暂时离开 |
| `end_circle_hopper` | **圈子浪人** | 62 | 400h+、circle.count ≥ 4、flag `circle_hopper` | 你哪里都待过，哪里都不属于你 |
| `end_gearhead` | **设备折腾家** | 58 | 250h+、coding ≥ 30、`gearhead` | 你一半时间在玩游戏，一半在修设备 |
| `end_tracker_dancer` | **全身追踪的人** | 56 | 300h+、`全身追踪`、dance ≥ 36 | 你会动脚了，这件事改变了一切 |
| `end_night_dancer` | **深夜的独舞者** | 54 | 250h+、dance ≥ 30、friends ≤ 30、`夜猫子` | 凌晨的舞房只有你一个人 |

> 与本体结局的关系：`end_mediator` / `end_best_friend` 优先级高于 `end_leader`（78）之下，
> 用来在「社区领袖」和「好友很多但都不算朋友」之间切分。
> `end_tracker_dancer` 与本体 `end_performer`（53）条件相近但要求 `全身追踪`，是**设备维度的版本**。

新增 `endingHint.path`：`mediator`、`best_friend`、`reunion`、`circle_hopper`、`gearhead`、`tracker`、`night_dancer`。
