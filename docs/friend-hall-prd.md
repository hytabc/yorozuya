# 交友厅需求设计 PRD

## 1. 背景与目标

在现有“砂糖社”之前新增“交友厅”，为 VRChat 社区成员提供公开自我介绍、照片展示和好友申请入口。交友厅复用砂糖社的卡片式视觉语言，但好友关系独立于砂糖关系管理。

目标：

- 用户可以登记、编辑、删除交友资料，并管理个人照片。
- 照片上传后必须经过内容审核，审核通过前只有资料主人和审核人员可见。
- 其他用户可以从资料详情发起好友申请；资料主人可以同意或拒绝。
- 已同意的好友关系计入双方好友数，页面顶部展示好友数最多的前三名用户。
- 交友厅在主导航和页面访问顺序上位于“砂糖社”之前。

## 2. 范围与非目标

### 本期范围

- 登录用户访问 `/friends`、浏览交友资料、查看详情。
- 每个用户最多一份交友资料，包含 1 至 1000 字介绍和最多 5 张照片。
- 单张照片最大 5 MiB，支持 JPEG、PNG、GIF、WebP。
- 照片删除、追加上传、资料编辑和资料删除。
- 好友申请的发起、待处理列表、同意、拒绝和取消。
- 好友数排行榜前三名。
- 内容审核台查看、屏蔽和恢复交友厅照片。

### 非目标

- 不新增站内聊天系统；成为好友后仍使用现有 QQ 等联系方式。
- 不改变砂糖社档案、砂糖关系和砂糖榜逻辑。
- 不把好友关系用于委托接取权限或其他业务权限。

## 3. 用户流程

1. 登录用户进入“交友厅”，浏览资料卡片和好友榜。
2. 用户点击“登记资料”填写介绍并上传照片；照片进入“审核中”，主人仍可在编辑器中查看和删除。
3. 用户点击其他人的卡片查看详情；若双方没有关系，可点击“申请添加好友”。
4. 被申请人可在交友厅的“好友申请”区域查看申请并选择“同意”或“拒绝”。申请人可以取消自己发出的待处理申请。
5. 同意后关系状态变为好友，双方好友数各增加 1；详情中显示双方已登记的 QQ（若未填写则显示未填写）。
6. 用户可以随时编辑/删除资料。删除资料不会删除已建立的好友关系，但该用户将从公开资料列表中移除；好友数保留在排行榜中，直到好友关系被解除（本期不提供解除好友入口）。

## 4. 功能需求

### 4.1 资料列表与详情

- 资料列表只展示 `is_active=true`、非管理员且已登记交友资料的用户。
- 卡片展示首张审核通过照片、昵称、介绍摘要和好友数；没有审核通过照片时使用无照片占位。
- 详情展示所有审核通过照片、完整介绍、好友数和关系状态。
- 屏蔽照片仅资料主人和审核人员可见，并显示审核理由；其他用户不收到该照片。
- QQ 仅资料主人本人或已成为好友的双方可见。

### 4.2 资料编辑

- 新建资料时介绍必填，至少上传 1 张照片；编辑时可追加照片，照片总数不超过 5 张。
- 单次请求最多上传 5 张，单张不超过 5 MiB；服务端校验文件签名和数量，不能只信任 MIME。
- 上传照片默认 `is_visible=false`，等待审核；重新上传/追加照片不会影响已通过照片。
- 用户只能删除自己的照片和资料。删除资料同时删除其照片文件和数据库记录。

### 4.3 好友申请

- 不能向自己发起申请；管理员账号不能登记或申请好友。
- 只有双方均存在交友资料时才允许申请。
- 同一对用户最多一条关系记录：`pending`、`accepted`、`rejected`。拒绝后可再次申请，申请时复用记录。
- 待处理申请只有被申请人可以同意或拒绝，申请人可以取消。
- 已同意关系不重复计数，也不能再次申请。

### 4.4 好友榜

- 按已同意关系数降序排序，最多返回 3 名用户。
- 同数时按资料更新时间升序、用户 ID 升序保证结果稳定。
- 榜单展示用户昵称、审核通过的首张照片和好友数。

### 4.5 审核

- 内容审核人员（现有 `get_content_moderator` 权限）可查看所有交友厅照片。
- 屏蔽必须填写 1 至 200 字理由；恢复时清空理由。
- 管理端列表显示主人、照片、审核状态和操作按钮。

## 5. API 设计

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/friends/profiles` | 资料卡片列表 |
| GET | `/api/friends/profiles/{user_id}` | 资料详情与当前关系 |
| GET | `/api/friends/top` | 好友数前三名 |
| POST | `/api/friends/profile` | 新建/编辑资料（multipart） |
| DELETE | `/api/friends/photos/{photo_id}` | 删除本人照片 |
| DELETE | `/api/friends/profile` | 删除本人资料 |
| GET | `/api/friends/requests/mine` | 当前用户待处理申请 |
| POST | `/api/friends/requests/{target_user_id}` | 发起/重新发起申请 |
| POST | `/api/friends/requests/{request_id}/accept` | 同意申请 |
| POST | `/api/friends/requests/{request_id}/reject` | 拒绝申请 |
| DELETE | `/api/friends/requests/{request_id}` | 申请人取消申请 |
| GET | `/api/admin/friends/photos` | 审核列表 |
| PATCH | `/api/admin/friends/photos/{photo_id}` | 屏蔽/恢复照片 |

## 6. 数据模型

- `FriendProfile(id, user_id unique, about, created_at, updated_at)`。
- `FriendPhoto(id, profile_id, file_path unique, is_visible, admin_note, moderated_by_id, moderated_at, created_at)`。
- `FriendRequest(id, user_a_id, user_b_id, requester_id, status, created_at, responded_at)`；`user_a_id < user_b_id`，对用户对建立唯一约束。

## 7. 页面与导航

- 新增 `FriendHall.vue`，布局、卡片、资料编辑弹窗沿用 `SugarClub.vue` 的视觉规范。
- 路由为 `/friends`，需要登录；页面统计 key 为 `friends`。
- 桌面导航和移动菜单顺序：地图推荐 → 交友厅 → 砂糖社。
- 交友厅内部顺序：好友榜 → 好友申请 → 交友名片。

## 8. 验收标准

- 生产数据库升级后无需手工建表，服务启动自动创建新增表。
- 上传第 6 张照片、超过 5 MiB 或伪造图片扩展名均被拒绝。
- 未审核照片不出现在其他用户的列表和详情中；审核人员和主人可见。
- 好友申请的权限、重复申请、同意/拒绝/取消状态符合本 PRD。
- 好友榜只返回前三名且数量准确。
- `backend` 测试覆盖资料 CRUD、图片限制/审核、申请状态和排行榜；前端生产构建通过。
