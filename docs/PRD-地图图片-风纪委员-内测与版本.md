# 万事屋地图图片、风纪委员、内测与版本 PRD

版本：V0.1-Beta  
日期：2026-09-08

## 背景与目标

地图推荐现有图片能力仅支持用户在提交后单张上传，且同一用户重复上传会替换旧图。社区需要在推荐提交时快速附图，也需要更完整的内容审核分工、内测用户标记及公开的版本说明。

本期目标：

- 地图推荐创建时可选传 0 至 3 张图片。
- 已有地图可一次补传 1 至 5 张图片，每个地图累计最多 5 张。
- 新增独立的风纪委员角色，专职图片审核及委托/地图举报处理。
- 所有用户持久化保存“是否内测用户”标记，由超级管理员维护。
- 全站展示当前版本 `V0.1-Beta`，并提供公开版本更新页面。

## 用户与权限

| 能力 | 普通/志愿者 | 风纪委员 `disciplinarian` | 管理员 `staff` | 超级管理员 |
|---|---:|---:|---:|---:|
| 地图提交与上传 | 是 | 是 | 是 | 是 |
| 审核头像、用户图片、砂糖社图片、地图图片 | 否 | 是 | 是 | 是 |
| 处理委托、地图推荐举报 | 否 | 是 | 是 | 是 |
| 用户角色、接单上限、密码、反馈管理 | 否 | 否 | 是 | 是 |
| 授予/撤销风纪委员、内测用户标记 | 否 | 否 | 否 | 是 |

风纪委员不继承管理员、看板娘或志愿者的额外权限。前端审核台只展示其被授权的举报和图片审核功能。

## 功能需求

### 地图图片

1. `POST /api/vr-maps` 同时兼容原 JSON 创建和 multipart 创建；multipart 字段为 `name`、`description`、`category` 和可重复的 `photos`。
2. 创建时最多 3 张；补图接口 `POST /api/vr-maps/{id}/photos` 单次最多 5 张；一张地图累计最多 5 张。
3. 图片仅支持 PNG/JPG；每张不超过 10 MB；每次请求图片总大小不超过 30 MB。后端先完整校验，再写入文件，失败不产生部分文件记录。
4. 所有新图片默认待审核，审核通过才对公众可见；上传者和审核人员可见待审/驳回图片。
5. 旧的单用户单地图照片数据库唯一索引在 SQLite 迁移时删除，已有图片不丢失。

### 风纪委员与内测用户

1. `User.role` 增加 `disciplinarian`，显示名为“风纪委员”。角色授权与撤销仅限超级管理员。
2. 用户增加 `is_beta_tester`，默认 `false`；超级管理员通过 `PATCH /api/admin/users/{id}/beta-tester` 更新。
3. 用户自身、资料返回和后台用户列表均包含该标记，供后续内测功能和福利规则消费。

### 版本页

1. 主导航及全局页脚提供版本入口；页脚恒显示当前版本 `V0.1-Beta`。
2. `/versions` 公开展示版本记录。V0.1-Beta 作为首个版本，概述委托、社区、地图、砂糖社及运营审核能力。

## 验收标准

1. 创建推荐可附 1 至 3 张待审图片，创建成功后上传者可见、访客不可见。
2. 已有推荐可一次传多张；第 6 张或第 6 个累计图片请求返回 422；单张超过 10 MB、总量超过 30 MB 返回 422。
3. 风纪委员可处理规定的审核与举报接口，访问用户管理、反馈、公告运营接口返回 403。
4. 超级管理员可切换任意用户的内测标记，重新获取 `/auth/me` 可见准确值。
5. 桌面和移动端均可访问版本页，页面显示 `V0.1-Beta` 和首版能力说明。
