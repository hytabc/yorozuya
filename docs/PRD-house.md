### 🧩 可参考的开源项目

**体素编辑器（制作自定义家具的核心）**
* **VoxoB**：纯浏览器端体素编辑器，MIT协议，零安装，支持导出OBJ/GLB
* **nimadez/voxel-builder**：功能完整，支持体素化导入模型，可导出GLB/OBJ，适合制作家具
* **gharielsl/voxel-mesh-editor**：TypeScript编写的Web体素编辑器，代码结构清晰

**房间布置与2.5D/3D视图**
* **blueprint3d-modern**：Three.js + TypeScript，支持2D/3D切换、家具拖放、房间模板，本地IndexedDB存储，无需后端
* **wy51ai/floorplan-3d**：纯前端单HTML文件，60+家具库，2D平面布置一键切换3D漫游
* **CodeHole7/threejs-3d-room-designer**：React + Three.js，2D/3D双视图编辑家具位置与朝向

**多人联机/串门**
* **glink25/Parti**：Web平台与Runtime，支持创建多人互动房间，链接或二维码邀请朋友加入
* **webmattic/floorplanner**：支持实时协作，多用户编辑与共享光标

**体素+多人结合的参考**
* **voxelverse**：Unity + WebSockets的多人体素平台，实时同步，可参考其网络架构
* **voxel-world**：Vulkan体素沙盒，支持最多4人同步


### 📄 产品需求文档（PRD）

#### 一、项目概述
在现有网站中增加“2.5D房间布置”模块。玩家可使用预制家具，或基于 **64³ / 32³ / 16³** 立方体网格（每格颜色自定义）制作家具，布置在 **256×256×128** 的房间中，并支持互相串门。

#### 二、用户角色
* **普通玩家**：布置房间、制作家具、串门浏览
* **家具创作者**：使用体素编辑器制作并发布家具
* **游客**：通过分享链接浏览他人房间，无需登录

#### 三、功能需求

**3.1 体素家具编辑器**

| 功能 | 说明 |
|---|---|
| 网格尺寸选择 | 新建家具时可选64³/32³/16³ |
| 体素放置/删除 | 点击或拖拽在网格中放置/删除方块 |
| 颜色自定义 | 每格颜色可单独设置，支持色板 |
| 对称绘制 | 支持X/Y/Z轴镜像绘制，加速建模 |
| 家具保存/导出 | 保存到用户账户，导出为体素数据（JSON） |
| 预制家具库 | 官方预制家具，分类浏览（床/桌/椅/灯等） |

**3.2 房间布置系统**

| 功能 | 说明 |
|---|---|
| 房间尺寸 | 固定256×256×128（长×宽×高） |
| 2.5D视角 | 等距视角渲染，可旋转/缩放/平移 |
| 家具放置 | 从家具库拖入房间，支持旋转、移动、删除 |
| 碰撞检测 | 家具之间不可重叠 |
| 房间保存 | 自动保存到本地（IndexedDB），支持手动保存 |
| 地面/墙面材质 | 可自定义颜色或纹理 |

**3.3 串门系统**

| 功能 | 说明 |
|---|---|
| 房间分享 | 生成唯一链接，可分享到社交平台 |
| 访客模式 | 通过链接进入他人房间，只读浏览 |
| 访客交互 | 可点赞、留言，不可修改房间布置 |
| 在线状态（可选） | 显示当前在线串门的玩家 |

**3.4 用户系统**

| 功能 | 说明 |
|---|---|
| 注册/登录 | 邮箱或第三方登录 |
| 个人主页 | 展示自己的房间和创作的家具 |
| 家具发布 | 将自制家具设为公开，供他人使用 |

#### 四、技术方案建议

* **前端渲染**：Three.js（WebGL），2.5D等距视角通过正交相机实现
* **体素编辑**：使用 InstancedMesh 批量渲染体素，保证性能
* **数据存储**：家具与房间数据用 **IndexedDB** 本地存储；用户数据需后端（Node.js + PostgreSQL）
* **实时同步（串门）** ：WebSocket + 房间状态广播；若只需异步串门，可用 HTTP 轮询代替
* **技术栈建议**：
  - 渲染：Three.js + 可选 React Three Fiber（若用React）
  - 体素编辑器：参考 VoxoB 或 voxel-builder 的实现
  - 房间布置：参考 blueprint3d-modern 的架构

#### 五、数据模型（核心）

```json
// 家具数据
{
  "furnitureId": "uuid",
  "name": "木椅",
  "gridSize": 16,
  "voxels": [
    { "x": 0, "y": 0, "z": 0, "color": "#8B4513" },
    ...
  ],
  "creator": "userId",
  "isPublic": true
}

// 房间数据
{
  "roomId": "uuid",
  "ownerId": "userId",
  "size": { "x": 256, "y": 256, "z": 128 },
  "furniturePlacements": [
    {
      "furnitureId": "uuid",
      "position": { "x": 64, "y": 0, "z": 32 },
      "rotation": 90
    }
  ]
}
```

#### 六、开发路线图（建议）

* **阶段一（核心编辑）** ：体素编辑器 + 房间2.5D布置，本地保存
* **阶段二（用户系统）** ：注册登录、家具发布、房间保存到云端
* **阶段三（串门）** ：房间分享链接、访客浏览、异步留言
* **阶段四（实时协作/串门）** ：WebSocket实时同步，多人同时在线

#### 七、潜在风险与对策

* **性能问题**：体素数量可能很大，需用 InstancedMesh 和分块加载
* **移动端适配**：体素编辑器在触屏上操作需专门设计交互
* **存储限制**：IndexedDB 有容量上限，大型房间需后端存储
