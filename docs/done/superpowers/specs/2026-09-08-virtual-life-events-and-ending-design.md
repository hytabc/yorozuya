# 虚拟人生 · 房间事件 / 多句回复 / 图片消息 / 七日结局 — 设计 Spec

日期：2026-09-08 · 状态：已获用户批准（设计评审通过）
范围：仅虚拟人生模块（yorozuya 项目，`feature/virtual-life-local` 分支）。其他模块一律不动。

## 1. 背景与目标

虚拟人生已完成 7 个阶段的模块化改造：内容全部入库（Pack）、对话为节点图引擎、
剧本按 1~7 天编排、管理端可视化编辑、激活新包自动迁移旧存档。
本阶段（阶段 8）在此基础上增加四种紧密关联的叙事能力：

1. **房间事件**：房间里出现可点击的事件入口，点开后是群聊式弹窗——
   不同角色轮流说话，玩家点击推进，到选项点时玩家做选择。
2. **多句回复**：NPC 对话节点的台词与选项回复从固定一句升级为可连续多句。
3. **图片消息**：剧本的任何消息组可挂一张图；玩家端气泡里显示缩略图，
   点击全屏弹出，再点消失。
4. **七日结局**：第 7 天结束后迎来结局画面（回顾 + 管理员可配置文案 +
   重新开始）。**没有第八天。**

核心架构决策（已与用户确认）：四者统一为一套「消息流」格式——
消息组 = 说话人 + 多句台词 + 可选图片；NPC 私聊与房间群聊事件共用同一
播放引擎，只是皮肤不同。不另造第二套引擎。

## 2. 决策记录（用户逐项确认）

| # | 问题 | 决定 |
|---|---|---|
| 1 | 事件剧本结构 | **轻量线性**：一条主线往下播，可插入选项点；选项只影响接下来几句与属性结算，随后汇回主线 |
| 2 | 事件触发规则 | **每天一次**：当天玩过后标记完成（入口变灰打✓），「下一天」重置 |
| 3 | 事件内容是否按天 | **跟随 7 天体系**：每个事件配 7 份剧本（第 1~7 天），没有第八天 |
| 4 | 第 7 天点「下一天」 | **迎来结局**：结局画面 = 一周数据回顾 + 管理员可配置结局文案 + 「重新开始」（重置存档从第 1 天再来） |
| 5 | 事件说话人 | **在册 NPC + 自由路人**：NPC 自动带立绘/头像；路人只需名字 + emoji 或上传头像，不注册为 NPC |
| 6 | 图片消息范围与来源 | **事件与 NPC 私聊都支持**；图片复用现有后台上传（`POST /api/virtual-life/assets`），不支持外链 |

## 3. 数据模型

### 3.1 消息格式升级（Pack content 内）

NPC 对话节点（`content.dialogue[npcId][day].nodes`）：

```
// 旧
{ line: '……', choices: [{ label, effects, reply, next }] }
// 新
{ lines: ['……', '……'],            // 至少 1 句
  image: '/uploads/life/xxx.png',   // 可选，null/缺省 = 无图
  choices: [{ label, effects, replies: ['……'], replyImage: null, next }] }
```

事件（`content.events`，新增顶层数组）：

```
{
  id: 'evt-beach-commotion',
  roomId: 'beach-1024',             // 必须引用已配置的 room
  title: '海滩的骚动',
  icon: '❗',                        // emoji，入口按钮上显示
  scripts: [ dayScript ×7 ],        // 恰好 7 份，无第八天
}
dayScript = {
  messages: [ msgOrChoice... ]      // 线性序列
}
// 消息组：
{ speaker: { npcId: 'ache' }                     // 在册 NPC
  | { name: '围观群众', avatar: '🏖' 或 '/uploads/...' },  // 自由路人
  lines: ['……'], image: null }
// 选项点：
{ choice: { options: [
    { label: '挤进去看看', effects: { stats: { explore: 2 } },
      reply: [ msgOrMsg... ] },     // 分支消息组（仅消息，不嵌套选项点）
    ...
] } }
```

约束：选项的 `reply` 播完后主线继续（汇回），`reply` 内不允许再出现选项点；
选项点之后的下一条主线消息照常播放。事件选项的 `effects` 只允许 `stats`
（不允许 `bond`——好感度只属于私聊；后端校验直接拒绝事件里的 `bond` 键），
`stats` 语义与对话选项一致。

结局（`content.ending`，新增）：

```
{ title: '一周的尾声', text: '七天结束了……（管理员可自定义，支持多行）' }
```

### 3.2 存档扩展（schema v2 内兼容，不升版本号）

```
eventProgress: { day: 3, done: ['evt-beach-commotion'] }   // 与当前天数绑定
finished: false                                            // 已看过结局
```

- `eventProgress.day !== state.day` 时视为当日无进度（「下一天」天然重置）。
- `done` 里出现的已删除事件 id：校验时宽容剔除，不报错。
- `finished: true` 的存档：客户端直接展示结局画面，不进入游戏主界面。
- 「重新开始」不新增 API：客户端用活动包的 `initialState` 构建全新状态
  （`finished: false`、事件进度清空、第 1 天）走现有 PUT 存档接口（CAS 照常）。

### 3.3 迁移（启动时就地迁移，沿用既有惯例）

`migrate_pack_content` 增加：
- 节点 `line` → `lines: [line]`；选项 `reply` → `replies: [reply]`；补 `image/replyImage: null`。
- 缺 `events` → 补 `[]`；缺 `ending` → 补默认文案。
存档侧：缺 `eventProgress` → `{day: state.day, done: []}`；缺 `finished` → `false`。

## 4. 玩家端 UX

### 4.1 房间事件入口

- 场景区（`LifeScene`）在当前房间配置了事件且当日未玩时，显示事件按钮：
  `icon + title`（如「❗ 海滩的骚动」）。多个事件纵向排列。
- 当日已玩：按钮置灰 + ✓，点击提示「今天已经看过了，明天再来吧」。

### 4.2 群聊弹窗（`LifeEventModal.vue` 新组件）

- 仿微信群聊的对话流：每条消息组 = 头像 + 名字 + 气泡（多句台词逐句成泡）。
  在册 NPC 用包里立绘/头像；路人用 emoji 或上传头像。玩家本人的发言（选项）靠右。
- 推进方式：点击弹窗主体出下一组消息（沿用私聊「点击显示全文」的节奏感）；
  到选项点时暂停，底部弹出选项按钮，选择后：该选项的 reply 消息组插入播放，
  然后继续主线。
- 图片：气泡内缩略图（限宽），点击 → 全屏遮罩放大图，再点任意处消失。
  该「图片灯箱」做成独立小组件（`LifeImageLightbox.vue`），事件与私聊共用。
- 播完最后一条：显示「剧终」样式收尾，玩家点击关闭；关闭时写入
  `eventProgress.done` 并结算 effects（属性变更走现有 stats 通路）。

### 4.3 NPC 私聊升级

- 节点 `lines[]` 逐句播放（点一下一句，沿用现有打字机/点击显示全文交互）。
- 选项 `replies[]` 同理连续多句。
- 节点/回复带图时气泡内出缩略图，交互同 4.2 灯箱。
- 节点图引擎、分支、汇合、好感结算、存档 `dialogueNodes` 全部不变。

### 4.4 结局画面（`LifeEnding.vue` 新组件）

- 触发：第 7 天时「下一天」按钮替换为「🌙 迎来结局」；或载入到
  `finished: true` 的存档。
- 内容：全屏画面 = 管理员配置的 `ending.title` + `ending.text`
  + 自动回顾（各 NPC 最终好感、已探索地点 x/总数、手记篇数、本周玩过的事件数）。
- 「重新开始」按钮：二次确认后按 3.2 重置存档，回到第 1 天。

## 5. 管理端（/life-admin）

- **新「事件」区块**（`AdminEvents.vue`）：事件列表（按房间分组）+ 增删；
  编辑器为**线性剧本编辑器**（非思维导图）：消息卡片纵向排列，
  点卡片编辑说话人（NPC 下拉 或 路人名字+头像）、多句台词（可增删行）、
  图片上传；任意位置可插入选项点（选项含 label/effects/reply 消息组）。
  天切换沿用「第 1~7 天」页签。
- **剧本思维导图编辑器**：节点台词改为多行输入（可增删行）+ 图片上传；
  选项回复同样多行 + 图片。布局/交互不变。
- **新「结局」区块**：`ending.title` 一行输入 + `ending.text` 多行输入。
- 保存、校验报错透传、版本递增等机制不变。

## 6. 后端

- `validate_pack_content` 扩展：
  - `dialogue` 节点：`lines` 非空数组、`image` 仅允许 `/uploads/` 前缀或空；
    选项 `replies` 非空数组、`replyImage` 同图片规则。
  - `events`：`roomId` 必须存在于 rooms；`scripts` 恰好 7 份；消息组
    `speaker` 二选一（`npcId` 存在 或 `name` 非空）；`lines` 非空；
    选项点不嵌套；`effects` 仅允许 `stats` 键。
  - `ending`：`title`/`text` 非空字符串。
- 存档校验：`eventProgress` / `finished` 形状校验 + 宽容剔除未知事件 id。
- 种子：默认包新增 2~3 个示例事件（7 天连续小剧情）+ 结局文案；
  前端 `defaultPack.js` 与后端种子 JSON 由生成脚本保持 parity
  （`tests/lifeRegistry.test.mjs` 的相等断言继续生效）。

## 8. 风险与对策

- **迁移面变大**：8a 改动所有既有剧本数据形状——迁移函数必须幂等，
  用「已迁移数据再跑一遍不出错」的回归测试兜底。
- **parity 断言**：默认包结构变化必须前后端同步改（生成脚本重跑），
  否则 `lifeRegistry` 测试会红——把它当作守门员而非障碍。
- **真实库迁移不可逆**：8a 完成、E2E 过后，真实库重启即就地迁移旧包；
  沿用阶段 7 的激活迁移语义，不兼容存档保留原样。
- **范围蔓延**：多结局判定、事件嵌套选项、外链图片均已明确排除，
  后续需要时单独立项。
