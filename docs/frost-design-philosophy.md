# 糖霜世界关卡设计哲学与创作指南

> 基于24关的设计经验总结，供未来扩展或其他因果重组游戏参考。

---

## 🎯 核心设计原则

### 1. 因果重组的本质
**不是改变"发生了什么"，而是改变"先发生了什么"。**

#### 黄金法则
- ❌ **错误**：同一句话，在不同排列里变成不同的文字
- ✅ **正确**：同一句话，因为前后语境不同，含义完全改变

#### 经典案例
- **2-3「砂糖的诞生」**：「最近还好吗」排在换Avatar之前=关心，排在之后=质问
- **3-2「已读不回」**：「算了，我随口问的」排在等待前=主动收回，排在后=自我否定
- **5-1「被屏蔽的人」**：愤怒排在反思前=消化情绪，排在后=筑起防御墙

### 2. 碎片的情感价值（valence）
```
-2: 强负面（伤害、背叛、崩溃）
-1: 负面（疏远、犹豫、失落）
 0: 中性（事实陈述、观察）
+1: 正向（理解、温暖、尝试）
+2: 强正向（连接、治愈、领悟）
```

**平衡原则**：
- 每关总valence应在 -5 到 +10 之间
- good结局路径：总valence > 3
- true结局路径：总valence > 5，且包含至少一个关键领悟
- bad结局路径：总valence < 0

### 3. 碎片类型的运用

#### Gray（灰色）：锚点
- **用途**：固定起点和终点，不可拖动
- **设计**：起点描述初始状态，终点通常是中性的结果或领悟
- **示例**：「系统提示：XXX成为了你的第一位好友」

#### White（白色）：主要叙事
- **用途**：可拖动的核心事件
- **设计**：单一动作或观察，不要包含因果链
- **示例**：「澪说了一句话」vs「澪说了一句话，然后对方生气了」（❌后者包含了因果）

#### Gold（金色）：关键交换
- **用途**：决定性的选择或时机
- **设计**：通常带【关键】标记，权重25-35
- **示例**：「澪按下了'进入'键」「栞说：我们十二点一起下线，好吗？」

#### Red（红色）：负面引擎
- **用途**：负面情绪或冲动，位置决定破坏力
- **设计**：越靠前破坏力越大，被善意碎片隔开则淡化
- **示例**：5-1的「愤怒」、3-1的「嫉妒」

#### Blue（蓝色）：洞察碎片
- **用途**：角色内心独白，达成特定结局后解锁
- **设计**：不参与排列，只作为奖励阅读
- **示例**：「【澪的独白】我以为……原来……」

## 📐 约束系统设计

### 1. 约束类型与权重

#### before（顺序约束）
```javascript
{ "kind": "before", "a": "frag_X", "b": "frag_Y", "weight": 20-25 }
```
- **含义**：X必须排在Y之前
- **权重**：次要因果20，重要因果25
- **用途**：建立因果链

#### adjacent（相邻约束）
```javascript
{ "kind": "adjacent", "a": "frag_X", "b": "frag_Y", "weight": 30-35 }
```
- **含义**：X和Y必须紧挨着
- **权重**：通常最高（30-35）
- **用途**：强调紧密连接（对话的立即回应、动作的即刻反应）

#### position（位置约束）
```javascript
{ "kind": "position", "frag": "frag_X", "index": 2, "weight": 25 }
```
- **含义**：X必须排在第index位（0-based，不含锚点）
- **权重**：25
- **用途**：强制某个碎片出现在特定位置（通常用于bad结局）

#### group（分组约束）
```javascript
{ "kind": "group", "frags": ["frag_A", "frag_B", "frag_C"], "weight": 25-30 }
```
- **含义**：A、B、C必须连续出现（顺序不限）
- **权重**：25-30
- **用途**：强调一组碎片必须聚在一起（如8-3的三段回忆）

### 2. Anti约束（负面约束）
```javascript
"anti": [
  { "kind": "before", "a": "frag_X", "b": "frag_Y", "weight": 30-40 }
]
```
- **含义**：如果X排在Y之前，扣分
- **用途**：惩罚错误的因果顺序
- **权重**：通常比正向约束高（30-40）

### 3. 满分100的权重分配

#### 标准模板（good结局，threshold=70）
```javascript
"constraints": [
  { /* 关键因果 */, "weight": 25 },
  { /* 次要因果1 */, "weight": 20 },
  { /* 次要因果2 */, "weight": 20 },
  { /* 收尾 */, "weight": 35 }  // adjacent通常最高
],
"anti": [
  { /* 错误排序 */, "weight": 30 }
]
```

#### True结局模板（threshold=75）
- 比good多1-2个高权重约束
- 通常要求更精确的排列（如特定的adjacent组合）

#### Bad结局模板（threshold=55）
- 较少的约束（3-4个）
- 或者使用position约束强制错误位置
- Anti约束权重更高

## 🎭 结局设计的艺术

### 1. 四结局体系

#### Good（修复）
- **定位**：努力后的正向结果
- **标准**：问题得到解决，关系得到改善
- **文本**：温暖但不完美，留有成长空间
- **示例**：「先被理解，才有了解释的余地」

#### Bittersweet（苦甜）
- **定位**：不是最好，但也不是最坏
- **标准**：努力了，但时机不对或力度不够
- **文本**：淡淡的遗憾，不是谁的错
- **示例**：「理解来得太晚，她已经放下了」

#### Bad（崩坏）
- **定位**：错误的选择导致关系破裂
- **标准**：主动的破坏或完全的逃避
- **文本**：清晰的负面后果，可能不可逆
- **示例**：「防御墙一旦筑起来，谁也进不去」

#### True（真相/升华）
- **定位**：超越good的更高层次理解
- **标准**：不只是解决问题，而是领悟本质
- **文本**：既温暖又有深度，点出主题
- **示例**：「不是'你需要'，而是'我们都需要'」
- **解锁**：hidden，需要更精确的排列

### 2. 多个正向结局的设计

#### 适用场景
- 没有唯一"正确答案"的议题
- 主动 vs 被动都合理的情况
- 不同价值观都值得尊重的选择

#### 案例：6-1
- **good「被拉进来」**：有人主动把你拉进圈子
- **true「识趣地离开」**：你选择不强行融入
- **哲学**：两者都是成熟的选择，没有高下之分

#### 设计要点
- 两个正向结局的文本长度、情感强度应相当
- bondEffect差距不要太大（±3以内）
- 给玩家明确的价值信号：两条路都值得走

### 3. 无Happy Ending的设计

#### 适用场景
- 现实无法改变的困境（如7-3的消失）
- 需要面对失去的议题
- 教育玩家"不是所有问题都有完美解"

#### 案例：7-3「最后在线217天前」
- **good「灯一直开着」**：保留名字，不执着等待（valence=0）
- **true「谢谢你来过」**：最后一条消息是祝福（valence=+1）
- **bad「删除」**：切断最后的连接（valence=-2）
- **没有**：那个人回来了（现实不允许）

### 1. 碎片数量建议

| 章节 | 碎片数（含锚点） | 可移动碎片 | 难度 |
|------|----------------|----------|------|
| 1-1（教程）| 6 | 4 | 极易 |
| 1-2/1-3 | 8-9 | 6-7 | 易 |
| 2-X | 8-9 | 6-7 | 中 |
| 3-X | 9-11 | 7-9 | 中偏难 |
| 4-X | 9-10 | 7-8 | 难 |
| 5-X | 9 | 7 | 中 |
| 6-X | 9-10 | 7-8 | 中 |
| 7-X | 9-10 | 7-8 | 难 |
| 8-X | 10-11 | 8-9 | 最难 |

### 2. 混沌率控制

| 难度 | 混沌率 | 设计意图 |
|------|--------|---------|
| 教程 | 50-60% | 试错空间大，鼓励探索 |
| 简单 | 40-50% | 容易找到正确排列 |
| 中等 | 30-45% | 需要理解因果 |
| 困难 | 25-35% | 需要精确排列 |
| 最难 | 20-30% | 只有少数排列命中 |

### 3. 渐进式复杂度
```
1-1: 4个可移动碎片，1个关键约束
   ↓
2-3: 6个可移动碎片，4个约束，1个金色碎片
   ↓
4-3: 8个可移动碎片，4个约束，1个蝴蝶效应，分组约束
   ↓
8-3: 9个可移动碎片，4-5个约束，复杂的分组与adjacent组合
```

## 💡 主题选择与深度

### 1. 适合因果重组的主题

#### ✅ 优秀主题
- **沟通时机**：同样的话，说早了vs说晚了
- **情绪顺序**：愤怒→反思 vs 反思→愤怒
- **主动被动**：先伸手vs被拉进来
- **察觉行动**：先观察vs先行动
- **记忆顺序**：先想起美好vs先想起失去

#### ❌ 不适合的主题
- **外部随机事件**（如彩票中奖）：排列无法改变
- **纯粹的知识问答**：没有情感维度
- **单一路径必然**（如物理定律）：因果固定

### 2. 深度的四个层次

#### Level 1：表面行为
- 示例：「她说了A，对方回了B」
- 深度：低，只描述事实

#### Level 2：情感反应
- 示例：「她说了A，心里很忐忑」
- 深度：中，加入内心状态

#### Level 3：动机揭示
- 示例：「她说A不是想B，而是想C」
- 深度：高，揭示真实动机

#### Level 4：存在主义
- 示例：「她说A的时候，终于明白——关系不是……而是……」
- 深度：最高，触及人生哲理

**建议**：
- 每关至少达到Level 2
- True结局应达到Level 3-4
- 不要每关都Level 4（会显得说教）

### 3. VRChat特有主题清单

✅ **已用**：
- 第一次登入的紧张
- 砂糖关系的暧昧
- 第三者的无辜
- 社群的排他性
- 大群里的孤独
- 社群崩溃
- 过度依赖的陪伴边界
- Avatar与身份的距离
- 好友列表里永远灰掉的名字

💡 **可扩展**：
- World制作者的孤独与成就感
- 语言障碍（国际服的沟通）
- 时区差异（异国砂糖的困境）
- Avatar经济（买不起好看的模型）
- 公共活动中的表演焦虑
- Mirror前的自我审视
- 拍照文化与真实体验的冲突
- Desktop vs VR用户的体验差异
- 声音的重要性（失声/变声的影响）

### 1. 短程呼应（同章内）
- **2-1 → 2-3**：连续三晚 → 砂糖诞生
- **3-1 → 3-4**：澪的视角 → 悠的视角

### 2. 长程呼应（跨章）
- **1-1 → 8-1**：「跟着我，别走丢啦」从栞到澪

## 🎨 文本写作的黄金法则

### 1. 碎片文本
- **长度**：15-40字
- **结构**：主语+动作+简短描述，不要复杂从句
- **示例**：
  - ✅「澪把手机翻过去，又翻回来，屏幕还是那个页面。」
  - ❌「澪因为等不到回复而感到焦虑，所以把手机翻来覆去地看。」

### 2. 结局文本
- **长度**：
  - Good/Bittersweet/Bad：150-200字
  - True：200-250字
  - Chaos：50-80字
- **结构**：
  1. 复述关键碎片的顺序（30%）
  2. 展开后果（40%）
  3. 点题或留白（30%）
- **示例**：
  ```
  [复述] 澪先想起了美好，再想起了失去。
  [后果] 她按下了「进入」，栞和凛已经在等她了。
  [点题] 今晚我依然登入，因为我想成为那个说「欢迎回来」的人。
  ```

### 3. Excerpt（摘录）
- **长度**：8-15字
- **作用**：结局的一句话总结，显示在UI上
- **风格**：诗意、意象化、留白
- **示例**：
  - ✅「有些沉默本身，就是答案。」
  - ❌「澪终于明白了要主动离开。」

### 4. 避免的表达
- ❌「那天TA学会了……」（太说教）
- ❌「原来……是这样的」（太直白）
- ❌「从此以后……」（过于童话）
- ✅ 用具体的画面和对话代替总结

### 5. 意象库
| 意象 | 适用场景 |
|------|---------|
| 灯 | 等待、希望、归处 |
| 雪 | 时间、覆盖、纯净 |
| 手 | 连接、伸出、接住 |
| 名字变灰 | 离开、消失 |
| 在线人数 | 归属、不孤单 |
| 退出键 | 边界、离开的勇气 |
| 房间的安静 | 孤独、现实 |
| 头显 | 现实与虚拟的边界 |

## 🧪 测试与迭代

### 1. 自检清单
- [ ] 每个结局都可达（至少一种排列）
- [ ] True结局不是唯一解（给玩家探索空间）
- [ ] Chaos提示有引导性（不只是"再试试"）
- [ ] 碎片文本独立可读（不依赖上下文才能理解）
- [ ] 结局文本有情感落点（不是流水账）
- [ ] 所有ID唯一且符合命名规范
- [ ] 权重相加 >= threshold

### 2. 玩家测试
询问测试者：
1. 你觉得哪个碎片最重要？（测试金色碎片是否突出）
2. 你第一次达成的是什么结局？（测试默认排列是否合理）
3. 达成True用了几次？（测试难度）
4. 这一关想表达什么？（测试主题是否清晰）
5. 有没有想吐槽的地方？（开放性反馈）

### 3. 数据分析
关注指标：
- **混沌率**：过高（>70%）=太难，过低（<20%）=太简单
- **True达成率**：理想值10-25%
- **平均尝试次数**：理想值3-8次
- **最常见的第一次结局**：应该是Bittersweet或Good

## 📚 推荐的创作流程

### Step 1: 主题确定（1小时）
1. 选择一个VRC相关的人际困境
2. 用一句话概括冲突
3. 确认这个冲突能通过"时机/顺序"改变结局

### Step 2: 结局设计（2小时）
1. 先写True结局的核心领悟
2. 倒推Good结局（正向但未升华）
3. 设计Bittersweet（努力了但时机不对）
4. 设计Bad（错误的选择）
5. 写Chaos提示

### Step 3: 碎片拆解（2小时）
1. 把故事拆成6-8个独立事件
2. 确定哪些是锚点（不可移动）
3. 选出1-2个金色碎片（关键时刻）
4. 考虑是否需要红色碎片（负面引擎）
5. 为每个碎片分配valence

### Step 4: 约束编写（3小时）
1. 为True结局写约束（最严格）
2. 为Good结局写约束（较宽松）
3. 为Bad结局写约束或Anti
4. 调整权重，确保相加=100
5. 确保阈值合理

### Step 5: 测试与调优（2小时）
1. 运行穷举校验
2. 手动测试每个结局
3. 调整混沌率（修改权重）
4. 润色文本
5. 添加Hint

### Step 6: 集成与最终测试（1小时）
1. 更新index.json
2. 检查ID冲突
3. 全流程测试
4. 文档更新

**总计：约11小时/关**

## 🏆 经典关卡分析

### 案例1：2-3《砂糖的诞生》
**为什么是基准关**：
- 约束设计最纯粹：4个before + 1个adjacent = 100分
- 主题最典型：同一句话的语境翻转
- 文本最克制：不说教，让玩家自己领悟
- True条件最优雅：金色碎片必须adjacent问候

**可借鉴**：
- 用adjacent强调"立即回应"的重要性
- Anti约束惩罚"质问在前"
- 蝴蝶效应揭示内心（嫉妒的本质）

### 案例2：3-2《已读不回》
**为什么独特**：
- 唯一没有"拯救"选项的关卡（玩家无法让栞早回）
- Chaos文本直接点破：「这里没有'把她找回来'的解法」
- 教育玩家：不是所有问题都能解决，只能改变自己的应对

**可借鉴**：
- 敢于设计"无能为力"的情境
- 把"放手"作为正向结局
- Chaos提示可以很直白

### 案例3：8-3《今晚你依然会登入吗》
**为什么是完美收尾**：
- 元叙事收束：观测者→澪→玩家自己
- 全作回忆：用group约束串联三段记忆
- 选择的仪式感：「指尖停在进入键上」
- 呼应开篇：从4-3到8-3，从陈述到疑问

**可借鉴**：
- 最终章可以打破第四面墙
- 用group约束强调"全部回忆缺一不可"
- 给玩家仪式感（慢动作、特写镜头感）

## 🎓 给新创作者的建议

1. **先模仿，再创新**：从改编2-3开始，改主题但保留结构
2. **一次只设计一个机制**：不要第一关就上蝴蝶效应+红色碎片+分组约束
3. **少即是多**：6个碎片做得精，胜过10个碎片做得烂
4. **测试是创作的一部分**：手动排列至少20次，感受玩家的视角
5. **不要怕简单**：难度曲线比单关难度更重要
6. **保存被删除的文本**：第一稿通常太啰嗦，但其中有好句子
7. **读你的文本三遍**：第一遍写，第二遍删，第三遍改
8. **相信留白的力量**：不要把一切都说透
9. **玩家比你想象的聪明**：他们能理解隐喻
10. **但也比你想象的需要引导**：Hint分三级是有原因的

---

**最后**：因果重组游戏的魅力在于——同样的故事，不同的顺序，完全不同的人生。这不是游戏机制，这是对现实的隐喻：我们无法改变发生了什么，但我们可以选择先关注什么。

愿每一个碎片都闪烁着人性的光。✨
