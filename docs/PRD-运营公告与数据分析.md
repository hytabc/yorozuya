# 万事屋社区运营、公告与数据分析 PRD

版本：1.1  
日期：2026-09-18（v1.1 增补页面曝光时长、游客/登录用户拆分与设备分档）

## 1. 背景与目标

社区日常通知目前缺少统一发布入口，运营人员也无法判断各功能的实际使用情况。本期新增独立的“看板娘”权限组、公开公告中心和基础页面访问分析，让社区运营可以在不获得用户管理或内容审核权限的前提下完成公告维护与活跃观察。

成功标准：

- 超级管理员可以授予或撤销看板娘角色。
- 看板娘可以独立维护网站公告、活动公告，并查看近 7/30/90 天页面活跃数据。
- 游客和登录用户可以在公告中心查看当前有效公告。
- 能准确回答“今天多少访客查看委托大厅、多少访客进入砂糖社”等问题。

## 2. 用户与权限

| 能力 | 普通用户/志愿者 | 管理员 `staff` | 看板娘 `mascot` | 超级管理员 |
|---|---:|---:|---:|---:|
| 查看公开公告 | 是 | 是 | 是 | 是 |
| 管理公告 | 否 | 否 | 是 | 是 |
| 查看运营分析 | 否 | 否 | 是 | 是 |
| 用户等级与内容审核 | 否 | 是 | 否 | 是 |
| 授予/撤销看板娘 | 否 | 否 | 否 | 是 |

角色内部值新增 `mascot`，显示名为“看板娘”。该角色不会继承管理员或志愿者能力，仍按普通用户规则发布、接取委托。看板娘不能进入监管台，管理员也不能进入运营台。

## 3. 功能需求

### 3.1 公告中心

- 主导航新增“公告”，游客可访问。
- 页面分为“网站公告”和“活动公告”两处，分别承载服务通知/规则调整与社区活动/报名安排。
- 公告包含：类型、标题、正文、发布状态、置顶状态、可选开始时间、可选结束时间、发布人、创建及更新时间。
- 仅展示已发布且处于有效时间窗口内的公告；置顶公告优先，同级按创建时间倒序。
- 空分区显示明确空状态，加载失败不影响其他页面。

### 3.2 运营台

- 看板娘和超级管理员可见“运营台”入口。
- 公告管理支持新建、编辑、发布/暂停、置顶、定时生效、定时结束和永久删除。
- 新公告默认是草稿；结束时间必须晚于开始时间；永久删除前二次确认。
- 数据分析支持近 7、30、90 天切换，展示今日 PV/UV、周期 PV/UV、每日 PV 趋势、各页面 UV/PV 排名。

### 3.3 页面埋点

本期覆盖：委托大厅、成员名录、留言板、地图推荐、砂糖社、公告中心、我的委托、个人设置、登录注册。

- PV：一次成功的前端路由进入记为一次浏览。
- UV：登录用户按用户 ID 去重；游客按来源 IP 的 SHA-256 摘要去重（刻意不采信客户端 `session_id`，否则伪造随机标识即可无限抬高独立访客）。
- 日界线与报表日期统一使用北京时间（UTC+8）。
- 同一访客跨页面分别计入各页面 UV，周期总 UV 只计算一次。
- **不落库原始** IP、User-Agent、来源地址、搜索内容或页面业务数据；游客标识仅以 SHA-256 摘要落库。设备信息只在服务端归入粗粒度类别（PC 端 / 手机端 / 平板 / 其他）后保存，UA 原文不入库。
- 原始访问事件保留 180 天，报表最多查询 90 天。
- 埋点属于可丢失统计数据，不触发业务数据库的逐次自动快照；公告等运营内容仍沿用原有快照策略。

## 4. 数据与接口

新增数据表：

- `announcements`：公告正文、类型、状态、展示时间窗口与作者。
- `page_views`：页面键、去重访客键、可选用户 ID、访问时间、**设备分档（v1.1）**。
- `page_dwells`：**页面曝光时长（v1.1）**——页面键、去重访客键、可选用户 ID、设备分档、单次停留秒数、记录时间。

新增接口：

| 方法与路径 | 权限 | 用途 |
|---|---|---|
| `GET /api/announcements` | 公开 | 查询当前有效公告，可按类型筛选 |
| `GET /api/operations/announcements` | 运营权限 | 查询全部公告 |
| `POST /api/operations/announcements` | 运营权限 | 新建公告 |
| `PUT /api/operations/announcements/{id}` | 运营权限 | 更新公告 |
| `DELETE /api/operations/announcements/{id}` | 运营权限 | 删除公告 |
| `POST /api/analytics/page-view` | 公开 | 写入页面访问事件 |
| `POST /api/analytics/page-dwell` | 公开 | **写入一次页面曝光时长（v1.1）** |
| `GET /api/operations/analytics?days=` | 运营权限 | 获取聚合分析（含曝光时长、游客/用户拆分与设备分布） |

### 4.1 v1.1 增补需求

- **页面曝光时长**：进入页面开始计时，仅在页面可见时累计；路由切换、切后台、关闭标签时各结算一次上报。前端将单次时长截断到 2 小时，后端 `PageDwellCreate` 再以 `le=7200` 兜底。看板按「平均每次曝光时长」排序展示停留最久的页面。
- **访客 vs 实际用户**：在总览、每日趋势、页面活跃三处都把「游客（未登录）」与「登录用户」拆开统计；总量口径（`total_views` / `total_visitors`）保持不变。
- **设备分档**：服务端按请求的 `Sec-CH-UA-Mobile` 与 UA 归类为 `desktop` / `mobile` / `tablet` / `other` 四档；Android 平板（含 Android 但不含 Mobile）归入平板，无法识别或历史数据归入其他。
- **图表呈现**：运营台数据看板改用 Chart.js（仅 `/operations` 路由懒加载，不进入首包），本地同源打包，无需调整 CSP。

## 5. 验收标准

1. 超级管理员授予 `mascot` 后，用户重新登录可看到运营台；管理员授予、撤销或修改看板娘均返回 403。
2. 看板娘访问用户列表、委托审核等监管接口返回 403；普通用户访问运营接口返回 403。
3. 草稿、未到开始时间、已过结束时间的公告不出现在公开接口；有效置顶公告排在普通公告前。
4. 同一匿名标识两次进入大厅产生 2 PV、1 UV；登录用户无论浏览器标识如何均按账号去重。
5. 大厅与砂糖社等所有约定路由均发出合法埋点，埋点失败不阻断页面导航。
6. 前端在桌面与移动端可完整查看公告、编辑公告及读取分析，不出现横向页面溢出或控件遮挡。
7. （v1.1）切换路由、切后台再回来、关闭标签三种路径各产生一条曝光时长记录；切后台期间不计入时长；单次时长超过 2 小时被截断。
8. （v1.1）数据看板可区分游客与登录用户的浏览/访客，并从设备维度看到 PC 端 / 手机端 / 平板 / 其他。
9. （v1.1）升级已有数据库时自动为 `page_views` 补齐 `device` 列，存量数据归入「其他」且不报错。

## 6. 非目标与后续

本期不包含点击级事件、自定义埋点配置、用户级访问明细、数据导出、公告已读回执、消息推送和复杂活动报名。后续可在匿名聚合原则下增加渠道来源、任务发布/接取转化漏斗和公告阅读统计。
